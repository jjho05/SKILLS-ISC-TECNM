# 4.1. Introducción al Lenguaje (Node.js)

Bienvenido al Backend. Aquí no hay ventanas, ni botones, ni CSS.
Solo datos, lógica y velocidad.

---

## 1. ¿Qué es Node.js?

Node.js **NO** es un lenguaje. Es un **Entorno de Ejecución (Runtime)** para JavaScript.
Permite correr JS fuera del navegador (en tu servidor, laptop, o tostadora inteligente).

### 1.1 El Motor V8
Node.js usa el mismo motor que Google Chrome: **V8**.
*   Escrito en C++.
*   Compila JS a Código de Máquina (JIT - Just In Time) nativo.
*   Es brutalmente rápido.

### 1.2 Libuv (El Héroe Silencioso)
Si V8 ejecuta el código JS, **Libuv** maneja el Sistema Operativo.
*   Acceso al disco duro (File System).
*   Redes (TCP/UDP).
*   Event Loop.
*   Thread Pool (para tareas pesadas como Criptografía).

---

## 2. single-Threaded vs Multi-Threaded

El concepto más importante de Node.js.

### 2.1 Modelo Tradicional (Java/PHP/Python)
*   **Blocking I/O:** Cada cliente crea un "Hilo" (Thread) nuevo.
*   Si tienes 16GB de RAM, puedes soportar ~10,000 hilos.
*   Si el hilo consulta la DB, se **duerme** esperando la respuesta. Memoria desperdiciada.

### 2.2 Modelo Node.js (Event Driven)
*   **Non-Blocking I/O:** Un solo hilo maneja 1,000,000 de clientes.
*   **Camarero en un Bar:**
    1.  Toma el pedido de la Mesa 1.
    2.  Pasa el pedido a la cocina (DB).
    3.  **Inmediatamente** va a la Mesa 2 (No se queda esperando en la cocina).
    4.  Cuando la cocina toca la campana (Callback/Promise), lleva la comida a la Mesa 1.
*   **Resultado:** Node.js es perfecto para I/O intensivo (APIs, Chats, Streaming). Malo para CPU intensivo (Edición de video).

## 3. Instalación y Primeros Pasos

### 3.1 NVM (Node Version Manager)
Nunca instales Node.js directo del instalador de la web. Usa NVM.
Te permite cambiar de versión (v18, v20, v22) con un comando.
```bash
nvm install --lts  # Instala la versión estable (Long Term Support)
nvm use --lts
node -v
```

### 3.2 El REPL (Read-Eval-Print Loop)
Escribe `node` en tu terminal.
```javascript
> 1 + 1
2
> const os = require('os');
> os.cpus().length
8
```
Presiona `Ctrl + C` dos veces para salir.

## 4. `global` vs `window`

En el navegador, el objeto global es `window`. En Node.js, eso no existe.
Tenemos `global`.

### 4.1 Lo que NO existe en Node
*   `window`
*   `document` (No hay DOM)
*   `alert()`
*   `localStorage` (No hay navegador)
*   `fetch` (Antes de Node 18, necesitabas librerías. Ahora es nativo).

### 4.2 Lo que SÍ existe (Variables Globales)
*   `__dirname`: Ruta absoluta de la carpeta actual.
*   `__filename`: Ruta absoluta del archivo actual.
*   `process`: Información del proceso actual (variables de entorno, argumentos).
    ```javascript
    console.log(process.env.PORT); // Leer variables de entorno
    process.exit(1); // Matar el proceso (Error)
    ```
*   `Buffer`: Para manipular datos binarios (archivos).

## 5. Sistema de Módulos (CommonJS vs ESM)

Node.js nació en 2009 usando **CommonJS** (`require`).
Hoy en día soporta **ES Modules** (`import`), pero el ecosistema está dividido.

### 5.1 CommonJS (CJS)
El estándar clásico. Síncrono y Dinámico.
```javascript
// math.js
function sumar(a, b) { return a + b; }
module.exports = { sumar };

// app.js
const { sumar } = require('./math'); // Puedes hacer require dentro de un if
```

### 5.2 ES Modules (ESM)
El estándar moderno (Node 14+). Asíncrono y Estático.
Para usarlo, debes poner `"type": "module"` en tu `package.json` o usar la extensión `.mjs`.
```javascript
// math.mjs
export function sumar(a, b) { return a + b; }

// app.mjs
import { sumar } from './math.mjs'; // OBLIGATORIO poner la extensión
```

### 5.3 ¿Cuál usar?
*   Si empiezas un proyecto nuevo en 2025: **Usa TypeScript** (que se compila a lo que sea).
*   Si usas JS puro: **ESM** es el futuro, pero **CJS** sigue siendo el rey en herramientas de build.

## 6. NPM (Node Package Manager)

No reinventes la rueda. Alguien ya escribió una librería para eso.
Es el registro de software más grande del mundo.

### 6.1 `package.json`
El DNI de tu proyecto.
```bash
npm init -y # Crea el archivo con defaults
```
```json
{
  "name": "mi-api",
  "version": "1.0.0",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js" // Hot Reload
  },
  "dependencies": {
    "express": "^4.18.2" // Código de producción
  },
  "devDependencies": {
    "nodemon": "^3.0.1" // Solo para programar
  }
}
```

### 6.2 Semantic Versioning (SemVer)
Explicando `^4.18.2`: MAJOR.MINOR.PATCH
*   **MAJOR (4):** Cambios que rompen compatibilidad (Breaking Changes).
*   **MINOR (18):** Nuevas funcionalidades (Compatible hacia atrás).
*   **PATCH (2):** Bug fixes (Compatible).
*   **`^` (Caret):** Instala la última MINOR/PATCH (ej. 4.19.0) pero NO la siguiente MAJOR (5.0.0). ¡Seguridad!
*   **`~` (Tilde):** Instala solo el último PATCH (ej. 4.18.9).

### 6.3 `node_modules` (El Agujero Negro)
Aquí se descargan las librerías. **NUNCA** lo subas a Git.
Crea un archivo `.gitignore`:
```text
node_modules/
.env
```

## 8. El Event Loop (Versión Backend)

En Node.js, entender las fases del Event Loop es vital para no bloquear el servidor.
A diferencia del navegador, aquí hay fases específicas.

### 8.1 Las Fases
1.  **Timers:** Ejecuta `setTimeout` y `setInterval`.
2.  **Pending Callbacks:** Errores de sistema (ej. TCP error).
3.  **Poll:** Recupera nuevos eventos I/O (lectura de archivos, peticiones de red). Aquí es donde Node pasa la mayor parte del tiempo.
4.  **Check:** Ejecuta `setImmediate`.
5.  **Close Callbacks:** Cierre de conexiones (`socket.on('close')`).

### 8.2 Microtasks (Promesas vs process.nextTick)
Tienen prioridad sobre todo lo anterior.
*   `process.nextTick()`: Se ejecuta **inmediatamente** después de la operación actual, antes que cualquier Promesa.
*   `Promise`: Se ejecuta después de nextTick.

## 9. File System (Sistema de Archivos)

En el navegador no puedes leer archivos del usuario (por seguridad). En Node.js tienes control total del disco.

### 9.1 Síncrono (Bloqueante)
**EVITA ESTO** en servidores web. Detiene todo hasta que termina de leer.
```javascript
const fs = require('node:fs');
const data = fs.readFileSync('archivo.txt', 'utf-8'); // El servidor se congela aquí
console.log(data);
```

### 9.2 Promesas (Asíncrono - Recomendado)
```javascript
const fs = require('node:fs/promises');

async function leer() {
    try {
        const data = await fs.readFile('archivo.txt', 'utf-8');
        console.log(data);
    } catch (err) {
        console.error("No existe el archivo");
    }
}
```

### 9.3 Streaming (Para archivos gigantes)
Si vas a leer un video de 1GB, no lo cargues todo a la RAM (`readFile`). Usa Streams.
```javascript
const stream = fs.createReadStream('video-4k.mp4');
stream.on('data', (chunk) => {
    console.log(`Recibí ${chunk.length} bytes`);
});
```

## 10. HTTP Server (Raw Node.js)

Antes de usar Express, mira cómo se hace "a mano".

```javascript
const http = require('node:http');

const server = http.createServer((req, res) => {
    // req: Request (Lo que pide el cliente)
    // res: Response (Lo que respondemos)

    if (req.url === '/' && req.method === 'GET') {
        res.writeHead(200, { 'Content-Type': 'text/plain' });
        res.end('Hola Mundo desde Node');
    } else if (req.url === '/json') {
        res.writeHead(200, { 'Content-Type': 'application/json' });
        res.end(JSON.stringify({ mensaje: 'Soy un JSON' }));
    } else {
        res.writeHead(404);
        res.end('Not Found');
    }
});

server.listen(3000, () => {
    console.log('Servidor corriendo en puerto 3000');
});
```

## 11. Streams y Buffers (Manejo de Memoria)

Node.js es famoso por manejar Streams (Flujos de datos).
Netflix usa Node.js precisamente por esto.

### 11.1 Buffers
Un pedazo de memoria cruda (bytes). JS maneja Strings (UTF-8), pero Node maneja Binarios.
```javascript
const buf = Buffer.from('Hola');
console.log(buf); // <Buffer 48 6f 6c 61>
console.log(buf.toJSON()); // { type: 'Buffer', data: [ 72, 111, 108, 97 ] }
```

### 11.2 Pipes (Tuberías)
Conectar una entrada (Lectura) con una salida (Escritura).
```javascript
// Copiar archivo gigante sin usar RAM
const fs = require('node:fs');
const lectura = fs.createReadStream('origen.iso'); // 4GB
const escritura = fs.createWriteStream('destino.iso');

lectura.pipe(escritura);
// La memoria usada será constante (~64KB), no 4GB.
```

## 12. Debugging en el Backend

Aquí no hay "Inspect Element".

### 12.1 `node --inspect`
Abre Chrome -> `chrome://inspect`.
Verás tu proceso de Node.js y podrás usar el Debugger de Chrome (Breakpoints, Console, Memory Profiler) para tu backend.

### 12.2 `console.trace()`
Te dice exactamente quién llamó a la función.
```javascript
function peligro() {
    console.trace("¿Quién me llamó?");
}
```

### 12.3 `util.debuglog`
Para logs que solo quieres ver en desarrollo.
```javascript
const debug = require('node:util').debuglog('FOO');
debug('Esto solo sale si ejecutas: NODE_DEBUG=FOO node app.js');
```

## 13. Deployment y Clusters (Escalabilidad)

Node es Single Threaded. Si tienes un CPU de 8 núcleos, estás desperdiciando 7.

### 13.1 Modulo Cluster
Clona tu aplicación en múltiples hilos (Workers) que comparten el mismo puerto TCP.
```javascript
const cluster = require('node:cluster');
const os = require('node:os');

if (cluster.isPrimary) {
    const cpus = os.cpus().length;
    for (let i = 0; i < cpus; i++) cluster.fork();
    
    cluster.on('exit', (worker) => {
        console.log(`Worker ${worker.process.pid} murió. Reemplazando...`);
        cluster.fork(); // Auto-restart
    });
} else {
    // Código del servidor normal (Express, etc)
    require('./server.js');
}
```

### 13.2 PM2 (Process Manager 2)
La herramienta estándar para producción.
*   **Keep Alive:** Si tu app crashea, la reinicia.
*   **Logs:** Maneja la rotación de logs.
*   **Cluster Nuxt:** `pm2 start app.js -i max` (Usa todos los núcleos automáticamente).

## 14. Módulos Core Esenciales (`path` y `os`)

Node te da herramientas para interactuar con el servidor.

### 14.1 `path` (Rutas universales)
Windows usa `\` y Linux usa `/`. Si hardcodeas `C:\Users`, tu código explota en Linux.
```javascript
const path = require('node:path');

// Unir rutas de forma segura
const rutaCompleta = path.join(__dirname, 'uploads', 'imagen.png');
// En Windows: C:\proyecto\uploads\imagen.png
// En Linux: /proyecto/uploads/imagen.png

// Obtener extensión
console.log(path.extname('foto.jpg')); // ".jpg"
```

### 14.2 `os` (Sistema Operativo)
Diagnóstico del servidor.
```javascript
const os = require('node:os');

console.log(os.freemem()); // Memoria libre (Bytes)
console.log(os.platform()); // 'win32', 'linux', 'darwin' (Mac)
console.log(os.cpus()); // Info detallada de cada núcleo
```

## 15. Patrón Observer (`EventEmitter`)

Casi todo en Node hereda de `EventEmitter` (Streams, HTTP Server, Sockets).
Es el sistema de publicación/suscripción nativo.

```javascript
const EventEmitter = require('node:events');
const emisor = new EventEmitter();

// 1. Suscribirse (Escuchar)
emisor.on('compra', (total) => {
    console.log(`Se realizó una compra de $${total}`);
    enviarEmailRecibo();
});

emisor.on('compra', (total) => {
    actualizarInventario();
});

// 2. Publicar (Emitir)
emisor.emit('compra', 500);
```
*   **Nota:** Es síncrono por defecto. Si el listener falla, detiene el resto.

## 16. Child Processes (Procesos Hijos)

Node es bueno gestionando I/O, pero malo comprimiendo video.
¿Solución? Llama a un programa externo (como `ffmpeg` o `python`).

### 16.1 `exec` (Comandos simples)
Ejecuta un comando de terminal y guarda toda la salida en un buffer (RAM).
Límite por defecto: 1MB.
```javascript
const { exec } = require('node:child_process');

exec('ls -lh', (error, stdout, stderr) => {
    if (error) return console.error(error.message);
    console.log(`Salida: ${stdout}`);
});
```

### 16.2 `spawn` (Flujos de datos)
Para procesos largos (ej. convertir video). Usa Streams.
```javascript
const { spawn } = require('node:child_process');

// Ejecuta "ping google.com"
const proceso = spawn('ping', ['google.com']);

proceso.stdout.on('data', (data) => {
    console.log(`Ping dice: ${data}`);
});

proceso.on('close', (code) => {
    console.log(`Proceso terminó con código ${code}`);
});
```
*   **Diferencia:** `exec` espera a que termine. `spawn` te da los datos en vivo.

## 17. Manejo de Errores Críticos

Si un error no se captura (`catch`), Node.js crashea y el servidor se apaga.

### 17.1 `uncaughtException`
El último recurso. Atrapa errores síncronos no manejados.
```javascript
process.on('uncaughtException', (err) => {
    console.error('CRITICAL ERROR:', err);
    // Recomendación: Reiniciar el proceso limpiamente
    process.exit(1);
});

// Esto haría crashear el servidor sin el handler
funcionInexistente(); 
```

### 17.2 `unhandledRejection`
Para Promesas que fallaron sin `.catch()`.
```javascript
process.on('unhandledRejection', (reason, promise) => {
    console.error('Unhandled Rejection at:', promise, 'reason:', reason);
    // En versiones nuevas de Node, esto también cerrará el proceso pronto.
});
```

## 18. Worker Threads (El verdadero Multi-Threading)

A diferencia de `Child Process` (que es otro programa), los `Worker Threads` comparten memoria (ArrayBuffer) con el padre. Súper rápido.

```javascript
/* main.js */
const { Worker, isMainThread, parentPort } = require('node:worker_threads');

if (isMainThread) {
    // Hilo Principal
    const worker = new Worker(__filename);
    worker.on('message', msg => console.log('Worker dijo:', msg));
    worker.postMessage('Trabaja!');
} else {
    // Hilo Secundario
    parentPort.on('message', (msg) => {
        // Simular trabajo pesado CPU
        let x = 0;
        while(x < 1e9) x++;
        parentPort.postMessage('Terminé ' + x);
    });
}
```
*   **Uso:** Procesamiento de imágenes, Criptografía, Machine Learning.

## 19. Seguridad Basica en Node.js

### 19.1 Evitar Eval
Nunca uses `eval()`. En el backend es acceso root garantizado para el hacker.

### 19.2 Validar Entradas
Node no tiene tipos en tiempo de ejecución. Si esperas un número y recibes un objeto, puede explotar.
Usa librerías como **Zod** o **Joi** incluso antes de usar Express.

### 19.3 Rate Limiting
Node es rápido, pero un ataque DDoS síncrono (ReDoS) puede tumbarlo.
Nunca uses Regex complejos con datos del usuario.

```javascript
// Malo (Vulnerable a ReDoS)
const regex = /(a+)+b/;
regex.test("aaaaaaaaaaaaaaaaaaaaaaaaaaaaa"); // Congela el CPU
```

## 20. El Futuro del Runtime (Node vs Deno vs Bun)

Node.js ya no es el único rey. Ryan Dahl (creador de Node) se arrepintió de sus errores y creó Deno.

### 20.1 Deno
*   **Seguro por defecto:** No tiene acceso a red ni disco a menos que le des permiso (`--allow-net`).
*   **TypeScript Nativo:** No necesitas `tsc`. Ejecuta `.ts` directo.
*   **Estándar Web:** Usa `fetch`, `window` igual que el navegador.

### 20.2 Bun (El Demonio de Velocidad)
*   Escrito en **Zig**.
*   Start-up time instantáneo (x3 mas rápido que Node).
*   Compatible con NPM (reemplaza `npm install` con `bun install` y vuela).
*   **Veredicto 2025:** Node sigue siendo el estándar empresarial. Bun es excelente para scripts y desarrollo local.
