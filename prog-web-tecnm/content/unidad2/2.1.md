# 2.1 Introducción al Lenguaje de Marcado

## 1. ¿Qué es realmente "La Web"?

Antes de escribir `<h1>Hola Mundo</h1>`, debemos entender dónde estamos parados.
La Web no es Internet.
*   **Internet:** Es la infraestructura física (cables, routers, fibra óptica) y los protocolos de transporte (TCP/IP). Es la carretera.
*   **La Web (WWW):** Es un servicio que corre *sobre* Internet. Es el tráfico que viaja por la carretera (coches, camiones).

### 1.1 El Origen: CERN, 1989
Tim Berners-Lee no quería hacerse rico. Quería que los físicos de partículas compartieran sus papers más fácil.
Inventó 3 cosas que siguen siendo los pilares hoy:
1.  **HTML (HyperText Markup Language):** El formato de los documentos.
2.  **URI (Uniform Resource Identifier):** La dirección única de cada documento (hoy URL).
3.  **HTTP (HyperText Transfer Protocol):** El idioma para pedir esos documentos.

---

## 2. La Genealogía del HTML: De SGML a HTML5

HTML no nació de la nada. Tiene padres y abuelos.

### 2.1 El Abuelo: SGML (Standard Generalized Markup Language)
En los 70s y 80s, los militares y el gobierno de USA necesitaban una forma de guardar documentos que durara 50 años.
*   **SGML** era un metalenguaje: Un lenguaje para crear lenguajes.
*   Era increíblemente complejo, estricto y pesado.
*   *Curiosidad:* HTML es un "hijo" (una aplicación) de SGML. Por eso heredó los corchetes angulares `< >`.

### 2.2 El Nacimiento de HTML (1991)
Tim simplificó SGML. Solo tenía 18 etiquetas iniciales.
*   Incluía `<h1>`, `<p>`, `<a>` y... sí, `<isindex>` (que ya murió).
*   No existía `<img>`. ¡La web era solo texto!

### 2.3 La Adolescencia Rebelde: HTML 3.2 y 4.01 (1997-1999)
Aquí empezó la "Guerra de los Navegadores".
*   Netscape inventaba etiquetas (`<blink>`).
*   Microsoft inventaba otras (`<marquee>`).
*   Era el caos. El W3C (World Wide Web Consortium) tuvo que intervenir para estandarizar.
*   **HTML 4.01 Strictly:** Fue el estándar de oro por una década. Separó estructura (HTML) de presentación (CSS).

### 2.4 El Error Histórico: XHTML (2000-2009)
El W3C pensó: "HTML es muy sucio. Vamos a hacerlo estricto como XML".
Nació **XHTML**.
*   Si no cerrabas una etiqueta (`<br>`), la página **daba error y no cargaba**.
*   Los desarrolladores lo odiaron. Era demasiado pedante para el mundo real.
*   Esto llevó a que Apple, Mozilla y Opera se rebelaran y formaran el **WHATWG**, creando HTML5 por su cuenta.

### 2.5 El Renacimiento: HTML5 (2014 - Presente)
HTML5 no es solo etiquetas. Es una plataforma de aplicaciones.
*   Ya no es SGML ni XML. Es su propio parser.
*   Trajo APIs nativas: Geolocalización, Canvas (Gráficos), Video/Audio (matando a Flash), LocalStorage.

## 3. XML (eXtensible Markup Language)

Aunque hoy JSON domina, XML sigue siendo el rey en la industria bancaria, gubernamental y empresarial (Enterprise).

### 3.1 ¿Qué es?
XML no hace *nada*. Solo estructura datos.
A diferencia de HTML, donde `<h1>` significa "Título Gigante", en XML tú inventas las etiquetas.

```xml
<biblioteca>
    <libro id="101">
        <titulo>El Quijote</titulo>
        <autor nacionalidad="es">Cervantes</autor>
        <precio moneda="EUR">20.50</precio>
    </libro>
</biblioteca>
```

### 3.2 Reglas de Oro (Well-Formed XML)
Para que un XML sea válido, debe cumplir reglas estrictas (a diferencia de HTML que aguanta todo):
1.  **Raíz Única:** Todo debe estar envuelto en un solo elemento padre.
2.  **Cierre Obligatorio:** Toda etiqueta abierta `<foto>` debe cerrarse `</foto>` o auto-cerrarse `<foto />`.
3.  **Case Sensitive:** `<Libro>` y `<libro>` son cosas distintas.
4.  **Atributos:** Siempre entre comillas. `id="1"` (Bien), `id=1` (Mal).

### 3.3 DTD y XSD (Validación)
¿Cómo sabe un banco que el XML de la factura es correcto?
Usan esquemas (Schemas).
*   **DTD (Document Type Definition):** El formato viejo.
*   **XSD (XML Schema Definition):** Un archivo XML que describe "El campo precio debe ser un número decimal con 2 dígitos".

### 3.4 XML vs HTML
| Característica | HTML | XML |
| :--- | :--- | :--- |
| **Propósito** | Mostrar datos (Presentación). | Transportar y guardar datos. |
| **Etiquetas** | Predefinidas (`p`, `div`). | Inventadas por ti (`paciente`, `factura`). |
| **Estricto** | No. El navegador intenta arreglar errores. | Sí. Si hay un error, se rompe (Draconian Error Handling). |
| **Estado** | Vivo (HTML Living Standard). | Maduro/Estable. |

## 4. JSON vs XML: La Batalla Moderna

En 2005, AJAX usaba XML (la "X" de AJAX). Hoy usamos JSON. ¿Por qué?

### 4.1 JSON (JavaScript Object Notation)
Nació literalmente de la sintaxis de objetos de JS.

**El mismo libro en JSON:**
```json
{
  "biblioteca": {
    "libro": {
      "id": 101,
      "titulo": "El Quijote",
      "autor": {
        "nombre": "Cervantes",
        "nacionalidad": "es"
      },
      "precio": 20.50
    }
  }
}
```

### 4.2 Comparativa Técnica
| Criterio | XML | JSON |
| :--- | :--- | :--- |
| **Verbocidad** | Alta. Muchas etiquetas de cierre repetidas `</titulo>`. | Baja. Solo llaves y comillas. Ahorra ancho de banda. |
| **Parsing** | Lento y complejo (DOM Parser). | Rapidísimo (`JSON.parse()` es nativo en JS). |
| **Tipos de Datos** | Todo es texto. El parser debe inferir si "20" es número o string. | Tiene tipos nativos: Number, String, Boolean, Array, Object, Null. |
| **Metadata** | Soporta atributos `<precio moneda="mxn">`. | No soporta atributos (tienes que crear campos extra). |
| **Uso Ideal** | Configuración compleja (Maven, Android Manifest), Documentos legales (Factura Electrónica SAT). | APIs REST, Configuración web (`package.json`), NoSQL (Mongo). |

## 5. La Web Semántica (Web 3.0 Real)

Tim Berners-Lee soñaba con una "Web Semántica" donde las máquinas pudieran entender el significado de la información, no solo mostrarla.

### 5.1 El Problema
Para Google, `<p>Dr. House</p>` y `<p>House M.D.</p>` son solo texto. No sabe si hablas de una casa, un doctor o una serie.

### 5.2 La Solución: Linked Data y RDF
Usando vocabularios estándar (como `schema.org`), podemos etiquetar el contenido.

```html
<!-- HTML Semántico Microdata -->
<div itemscope itemtype="http://schema.org/TVSeries">
  <span itemprop="name">House M.D.</span>
  <span itemprop="genre">Medical Drama</span>
</div>
```
Ahora Google sabe *exactamente* qué es. Esto alimenta los "Rich Snippets" en los resultados de búsqueda (estrellitas, precios, horarios).

## 6. Ingeniería del Navegador: Lo que pasa bajo el capó

Cuando escribes `index.html` y lo abres en Chrome, ocurre un proceso de ingeniería fascinante en milisegundos.

### 6.1 El Motor de Renderizado (Browser Engine)
Cada navegador tiene un "corazón" escrito en C++ que interpreta tu código.
*   **Blink (Google):** Usado por Chrome, Edge, Opera, Brave, Vivaldi. (Es un fork de WebKit).
*   **WebKit (Apple):** Usado por Safari (y todos los navegadores en iOS).
*   **Gecko (Mozilla):** Usado por Firefox. El único independiente que queda.

### 6.2 El Pipeline de Renderizado Crítico (Critical Rendering Path)
Esto es lo que define qué tan rápido carga tu web. Memorízalo.

1.  **Parsing HTML -> DOM:** El navegador lee los bytes, los convierte en caracteres, luego en tokens (`<`, `Tag`, `>`), y finalmente construye el **DOM Tree** (Árbol de Documentos).
    *   *Bloqueo:* Si el parser encuentra un `<script src="app.js">`, **se detiene por completo** hasta descargar y ejecutar el JS. Por eso ponemos los scripts al final del `<body>`.
2.  **Parsing CSS -> CSSOM:** Lee el CSS y construye el **CSSOM Tree** (CSS Object Model). Calcula qué estilos aplican a qué nodo.
3.  **Render Tree (El Árbol Visible):** Combina DOM + CSSOM.
    *   *Nota:* Si un elemento tiene `display: none`, **no entra** al Render Tree. Si tiene `visibility: hidden`, sí entra (aunque sea transparente).
4.  **Layout (Reflow):** Calcula la geometría matemática. "¿Cuánto mide este div en píxeles? ¿Dónde está exactamente?".
5.  **Paint:** Rellena los píxeles (colores, bordes, sombras).
6.  **Composite:** Compone las capas (como Photoshop) usando la GPU.

## 7. XML Avanzado: El Estándar Enterprise

Si trabajas en un Banco o Gobierno, toparás con esto.

### 7.1 Espacios de Nombres (Namespaces)
En XML, tú inventas etiquetas. ¿Qué pasa si tienes un XML que combina datos de dos empresas y ambas usan la etiqueta `<table>`? (Una para tablas de muebles, otra para tablas de datos).
**Solución:** `xmlns` (XML NameSpace).

```xml
<root xmlns:mueba="http://muebleria.com" xmlns:html="http://w3.org/html">
    <mueba:table>
        <mueba:material>Madera</mueba:material>
    </mueba:table>

    <html:table>
        <html:tr><html:td>Dato</html:td></html:tr>
    </html:table>
</root>
```

### 7.2 XPath (XML Path Language)
Es como SQL, pero para XML. Sirve para buscar nodos específicos en árboles gigantes.
*   `/biblioteca/libro[1]`: El primer libro.
*   `//libro[@precio > 20]`: Todos los libros (no importa profundidad) que cuesten más de 20.
*   **Uso Actual:** Selenium (para testing automático) usa XPath para encontrar botones en webs complejas.

### 7.3 XSLT (Extensible Stylesheet Language Transformations)
Es un lenguaje para transformar un XML en... ¡otra cosa! (HTML, PDF, otro XML).
*   *Magia:* Puedes tener tus datos en XML y usar una hoja XSLT para generar tu sitio web automáticamente.
*   Fue muy popular en los 2000s, hoy reemplazado por JSON + Frontend Frameworks.

## 8. Codificación de Caracteres: UTF-8 vs El Mundo

Si alguna vez has visto esto: `GarcÃ?a`, lee esto con atención.

### 8.1 ASCII (1963)
Solo 7 bits. 128 caracteres.
*   Incluye: A-Z, a-z, 0-9 y signos básicos.
*   No incluye: Ñ, acentos, Kanji, Emojis.
*   Estados Unidos estaba feliz, el resto del mundo no.

### 8.2 ISO-8859-1 (Latin-1)
8 bits. Agregó caracteres de Europa Occidental (Ñ, á, ü).
*   Fue el estándar de la web primitiva.

### 8.3 Unicode y UTF-8 (La Solución Final)
Unicode es una lista de TODOS los caracteres humanos (y Klingon y Emojis).
**UTF-8** es la forma de guardar esa lista en bytes de forma inteligente.
*   Si el caracter es A (ASCII), usa 1 byte.
*   Si es Ñ, usa 2 bytes.
*   Si es 💩, usa 4 bytes.
*   **Regla:** SIEMPRE usa `<meta charset="UTF-8">` al inicio de tu HTML.

## 9. Standards Mode vs Quirks Mode

¿Por qué ponemos `<!DOCTYPE html>` en la primera línea?

### 9.1 La Historia
En los 90s, las webs se hacían mal (sin estándares). Cuando los navegadores empezaron a respetar los estándares (CSS correcto), las webs viejas se rompían.

### 9.2 La Solución del Navegador
El navegador decide cómo renderizar basándose en el DOCTYPE.
*   **Quirks Mode (Modo Rarezas):** Si NO hay DOCTYPE, el navegador simula ser Internet Explorer 5.
    *   Modelo de caja incorrecto.
    *   CSS funciona raro.
    *   Es para compatibilidad con webs de 1999.
*   **Standards Mode (Modo Estándar):** Si ve `<!DOCTYPE html>`, usa el motor moderno HTML5.
    *   Todo funciona como esperas.

**Conclusión:** Si olvidas el DOCTYPE, tu sitio se verá diferente en cada navegador.

## 10. Conceptos Teóricos: Hipertexto vs Hipermedia

### 10.1 Hipertexto
Texto lineal (libro) vs Texto conectado (Web).
El concepto revolucionario fue el **Hipervínculo**: La capacidad de saltar de un contexto A a un contexto B instantáneamente. Esto imita cómo funciona el cerebro humano (asociación de ideas).

### 10.2 Hipermedia
Es la evolución. Ya no solo conectamos texto.
Conectamos Audio, Video, Imágenes, Scripts, Datos en tiempo real.
La Web moderna es un motor de Hipermedia distribuido.

## 11. Laboratorio de Código: Manipulación del DOM y XML

Vamos a usar JavaScript puro (Vanilla JS) para entender cómo el navegador ve estos lenguajes.

### 11.1 El DOM API (Document Object Model)
El HTML es texto. El DOM es memoria.
```javascript
// Crear un elemento desde cero (sin escribir HTML)
const nuevoDiv = document.createElement('div');
nuevoDiv.id = 'mi-caja';
nuevoDiv.style.border = '1px solid red';

// Crear texto
const texto = document.createTextNode('Hola Mundo desde JS');

// Unir piezas (Construir el árbol)
nuevoDiv.appendChild(texto);

// Inyectar en el documento real
document.body.appendChild(nuevoDiv);

console.log(nuevoDiv.outerHTML); 
// Output: <div id="mi-caja" style="border: 1px solid red;">Hola Mundo desde JS</div>
```

### 11.2 Parseando XML con JavaScript
El navegador tiene un parser de XML incorporado (`DOMParser`).
```javascript
const xmlString = `
<biblioteca>
    <libro><titulo>1984</titulo></libro>
</biblioteca>
`;

const parser = new DOMParser();
const xmlDoc = parser.parseFromString(xmlString, "application/xml");

// Leer datos (Igual que HTML)
const titulo = xmlDoc.getElementsByTagName("titulo")[0].childNodes[0].nodeValue;

console.log(titulo); // "1984"
```

### 11.3 El Error de XML (ParserError)
Si intentas parsear XML mal formado, el navegador no lo arregla (como en HTML). Te devuelve un documento de error.
```javascript
const xmlMalo = "<root><apertura>Sin cierre</root>";
const docError = parser.parseFromString(xmlMalo, "application/xml");

// El resultado es un documento XML que contiene información del error
console.log(docError.getElementsByTagName("parsererror").length > 0); // true
```

## 12. Deep Dive: Tipos MIME y Modos de Parsing

¿Cómo sabe el navegador si le estás enviando HTML, XML o una foto? No es por la extensión del archivo. Es por el **Content-Type** (MIME Type).

### 12.1 `text/html`
*   **Comportamiento:** El navegador usa el parser de HTML5.
*   **Tolerancia a fallos:** Infinita. Si olvidas cerrar un `</div>`, el navegador adivina dónde cerrarlo.
*   **Scripts:** Ejecuta `document.write()` (aunque no deberías usarlo).

### 12.2 `application/xhtml+xml`
*   **Comportamiento:** El navegador usa el parser XML estricto.
*   **Tolerancia a fallos:** CERO. Si hay un error de sintaxis, muestra la "Pantalla Amarilla de la Muerte" (Yellow Screen of Death) y deja de renderizar todo el sitio.
*   **Historia:** Fue el sueño de la Web 2.0 que fracasó. Nadie quería que su sitio dejara de verse por un error tipográfico.

### 12.3 `application/xml` o `text/xml`
*   **Comportamiento:** Muestra el árbol de nodos con colores y permite colapsar/expandir ramas. No aplica CSS por defecto (a menos que uses `<?xml-stylesheet?>`).
*   **Uso:** Feeds RSS, Sitemaps, Configuración.

## 13. Glosario Técnico de Lenguajes de Marcado

*   **Atributo:** Información extra en la etiqueta de apertura (`width="500"`).
*   **CDATA (Character Data):** En XML, una sección donde puedes escribir caracteres "prohibidos" (como `<` o `&`) sin que el parser intente interpretarlos. `<![CDATA[ if (a < b) ]]>`.
*   **Deprecado (Deprecated):** Una etiqueta u opción que "funciona, pero no deberías usarla" porque será eliminada en el futuro (ej. `<font>`, `<center>`, `<marquee>`).
*   **DOM (Document Object Model):** La representación en memoria (árbol de objetos) del HTML parsedo. Es lo que manipula JavaScript.
*   **Elemento vs Etiqueta:**
    *   *Etiqueta:* `<p>` (la marca).
    *   *Elemento:* `<p>Hola</p>` (la marca + el contenido + la marca de cierre).
*   **Entidad HTML:** Un código para escribir caracteres reservados.
    *   `&lt;` (<) Less Than
    *   `&gt;` (>) Greater Than
    *   `&amp;` (&) Ampersand
    *   `&nbsp;` (Non-Breaking Space).
*   **Parser:** El programa que lee texto plano y lo convierte en una estructura de datos útil.
*   **Polyfill:** Código (usualmente JS) que provee funcionalidad moderna en navegadores viejos.
*   **Semántica:** El "significado" del código. Usar `<footer>` en lugar de `<div id="footer">` ayuda a máquinas (Google) y humanos (ciegos) a entender qué es.
*   **Void Element (Elemento Vacío):** Etiqueta que no tiene contenido ni cierre. Ej. `<br>`, `<img>`, `<input>`, `<meta>`.

## 16. Web Components: El Futuro del Marcado

¿Por qué usar `<div class="slider">` cuando podrías usar `<mi-slider>`?
Los Web Components son la evolución final de HTML: la capacidad de crear tus propias etiquetas.

### 16.1 Los 4 Jinetes de los Web Components
1.  **Custom Elements:** Definir `<mi-boton>`.
2.  **Shadow DOM:** Un DOM aislado dentro de tu componente. El CSS de afuera no le afecta. ¡Adiós a conflictos de nombres!
3.  **HTML Templates:** La etiqueta `<template>` que el navegador no renderiza hasta que tú se lo pides.
4.  **ES Modules:** Importar JS estándar.

### 16.2 Ejemplo Real (Vanilla JS)
Así se crea una etiqueta nueva hoy en día, sin frameworks.

```javascript
class MiBoton extends HTMLElement {
    constructor() {
        super();
        this.attachShadow({ mode: 'open' }); // Crear Shadow DOM
    }

    connectedCallback() {
        // Cuando la etiqueta se pone en el HTML
        this.shadowRoot.innerHTML = `
            <style>
                button { background: purple; color: white; border: none; padding: 10px; }
            </style>
            <button>¡Soy un Web Component!</button>
        `;
    }
}

// Registrar la etiqueta
customElements.define('mi-boton', MiBoton);
```

Ahora puedes usar `<mi-boton></mi-boton>` en cualquier parte de tu HTML.

## 17. La Arquitectura de Accesibilidad (A11y OM)

Pensamos que solo hay dos árboles: DOM y CSSOM. Existe un tercero: el **Accessibility Tree**.

### 17.1 ¿Cómo lee un ciego la web?
El "Screen Reader" (como VoiceOver o NVDA) NO lee el DOM. Lee el Accessibility Tree.
Este árbol es una versión simplicada del DOM que solo contiene información semántica.
*   `div` -> Ignorado (Es solo decorativo).
*   `button` -> "Botón, clickable".
*   `img` -> "Imagen: [texto alt]".

### 17.2 WAI-ARIA (Web Accessibility Initiative - Accessible Rich Internet Applications)
A veces el HTML no alcanza. Si creas un div que actúa como botón:
```html
<!-- Malo: El ciego no sabe que es un botón -->
<div onclick="guardar()">Guardar</div>

<!-- Bueno: ARIA le dice al ciego "Esto es un botón" -->
<div role="button" aria-pressed="false" tabindex="0" onclick="guardar()">Guardar</div>
```
**Regla de Oro:** La mejor ARIA es no usar ARIA. Usa `<button>` nativo siempre que puedas.

## 18. SVG (Scalable Vector Graphics): XML Gráfico

Mucha gente olvida que SVG **ES** XML.
Puedes abrir un archivo `.svg` con el Bloc de Notas y leerlo.

### 18.1 Anatomía de un SVG
```xml
<svg width="100" height="100" xmlns="http://www.w3.org/2000/svg">
  <circle cx="50" cy="50" r="40" stroke="green" stroke-width="4" fill="yellow" />
</svg>
```
*   Es vectorial (matemático). No se pixela si haces zoom.
*   Es parte del DOM. Puedes cambiar el color del círculo con CSS: `circle:hover { fill: red; }`.

### 18.2 SVG vs Canvas
*   **SVG (Modo Retenido):** El navegador recuerda los objetos (círculo, cuadrado). Si mueves el círculo, el navegador lo repinta solo. Ideal para logos, iconos, gráficos simples.
*   **Canvas (Modo Inmediato):** Es un lienzo de píxeles tontos. Tu código JS dibuja. El navegador olvida qué dibujó. Ideal para juegos, 60 FPS, partículas.

## 20. Optimización: Minificación y Compresión

Tu código HTML legible para humanos es ineficiente para máquinas.

### 20.1 Minificación
El proceso de remover espacios en blanco, saltos de línea y comentarios.
*   *Original (45 bytes):*
    ```html
    <div class="box">
        <p> Hola </p>
    </div>
    ```
*   *Minificado (32 bytes):*
    ```html
    <div class="box"><p>Hola</p></div>
    ```
*   **Herramientas:** HTMLMinifier, plugins de Webpack/Vite.

### 20.2 Compresión (Gzip vs Brotli)
Antes de enviar el archivo por el cable, el servidor lo comprime.
*   **Gzip:** El estándar clásico (Algoritmo DEFLATE). Reduce el tamaño ~70%.
*   **Brotli (Google):** El estándar moderno. Reduce ~20% más que Gzip.
*   **Nota:** Si ves caracteres raros en la respuesta de red, es que el navegador no descomprimió bien (o el servidor mintió en el header).

## 21. Preguntas Frecuentes (FAQ) de Entrevista Senior

**1. ¿Cuál es la diferencia real entre `<b>` y `<strong>`?**
*   `<b>` (Bold): Es puramente visual. "Pon esto en negrita".
*   `<strong>` (Strong Importance): Es semántico. "Esto es importante". Los lectores de pantalla cambian el tono de voz.
*   *Respuesta:* Usa siempre `<strong>` a menos que sea algo decorativo.

**2. ¿Puedo poner un `<div>` dentro de un `<span>`?**
*   En HTML4: **ILEGAL**. Elementos de bloque no pueden ir dentro de elementos en línea.
*   En HTML5: Técnicamente el navegador lo permite, pero es mala práctica y confunde al parser. Cambia el `<span>` por un `<div>` con `display: inline-block`.

**3. ¿Qué hacen los atributos `data-*`?**
*   Permiten guardar datos privados en el HTML para que JS los lea.
*   Ejemplo: `<div data-user-id="123" data-role="admin">`.
*   JS: `element.dataset.userId`.

**4. ¿Por qué `window.onload` es diferente a `DOMContentLoaded`?**
*   `DOMContentLoaded`: Se dispara cuando el HTML y el DOM están listos (pero faltan imágenes).
*   `window.onload`: Se dispara cuando TODO (imágenes, iframes, estilos) terminó de cargar. (Mucho más lento).

## 22. Historia de los Estándares: La Guerra de los Navegadores

¿Por qué HTML5 es "vivo"?

### 22.1 W3C vs WHATWG
*   **1999-2004:** La W3C se obsesionó con XHTML (HTML estricto como XML). Era un desastre.
*   **2004:** Apple, Mozilla y Opera dijeron "No". Fundaron el **WHATWG**.
*   **2007:** WHATWG propuso HTML5 (pragmático, tolerante a errores).
*   **2019:** La W3C se rindió. HTML5 es ahora el **"HTML Living Standard"**. Ya no hay versiones (HTML6 no existirá), es una actualización contínua.

### 22.2 El proceso de un Estándar
1.  **Explainer:** Alguien dice "Necesitamos `<dialog>`".
2.  **Draft:** Se escribe la especificación técnica.
3.  **Implementation:** Chrome y Firefox lo construyen detrás de una "flag".
4.  **Ship:** Cuando 2 navegadores lo tienen estable, es oficial.

## 23. Cómo funciona el Parser HTML

Cuando Chrome lee tu código:
1.  **Tokenización:** Convierte el texto `<p>` en un objeto "StartTag: p".
2.  **Construcción del Árbol:** Crea el nodo `HTMLParagraphElement`.
3.  **Script Execution:** Si ve un `<script>`, PAUSA todo (a menos que uses `defer`).
4.  **Error Handling (La magia):**
    *   Si escribes `<p>Hola <div>Mundo</div></p>`, es ilegal (`div` dentro de `p`).
    *   El parser no explota. Lo reescribe silenciosamente a:
    *   `<p>Hola</p> <div>Mundo</div>`. (Cierra el p automáticamente).
    *   **Lección:** No confíes en que el navegador arregle tu código. Valídalo.
