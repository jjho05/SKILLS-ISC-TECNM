# 1.3 Tecnologías para el desarrollo de aplicaciones web

## 1. El Panorama Tecnológico (The Tech Landscape)

El desarrollo web ya no es solo HTML y PHP. Es un ecosistema complejo que evoluciona cada 6 meses.
Para navegar este caos, dividimos las tecnologías en capas de responsabilidad.

> **Regla de Oro:** "No aprendas herramientas, aprende fundamentos. Las herramientas cambian, los fundamentos (HTTP, DNS, Algoritmos) permanecen."

---

## 2. El Frontend Moderno: Ingeniería de Interfaces

El Frontend ha pasado de ser "diseño gráfico" a ser ingeniería de software compleja.

### 2.1 Los Tres Mosqueteros (La Base Inevitable)
No importa qué framework uses, al final todo se compila a estos tres:

1.  **HTML5 (Semántica y Estructura):**
    *   No es solo `<div>`. Es accesibilidad (`aria-labels`), SEO (`<meta>`) y APIs de dispositivo (Cámara, Geolocalización).
    *   *Evolución:* De `<div id="header">` a `<header>`.
2.  **CSS3 (Presentación y Animación):**
    *   Ya no necesitamos jQuery para animar. Flexbox y Grid revolucionaron el layout.
    *   *Variables CSS:* `--main-color: #ff0000;` nativo.
3.  **JavaScript (ES6+ / TypeScript):**
    *   Desde 2015 (ES6), JS es un lenguaje maduro (Clases, Módulos, Promesas, Async/Await).
    *   **TypeScript:** Es JavaScript con tipos (`string`, `int`). Se ha convertido en el estándar industrial para evitar errores ("undefined is not a function").

### 2.2 Frameworks de Componentes (La Guerra React vs Vue vs Angular)
Ya no escribimos páginas, escribimos **Componentes** (piezas de LEGO reutilizables).

| Framework | Creador | Filosofía | Curva de Aprendizaje | Uso Ideal |
| :--- | :--- | :--- | :--- | :--- |
| **React** | Meta (Facebook) | "Es solo una librería". Flexibilidad total. JSX. | Media. Requiere aprender hooks. | Todo. Es el estándar del mercado laboral. |
| **Vue.js** | Evan You | "El Framework Progresivo". Mezcla lo mejor de React y Angular. | Baja. Muy intuitivo. | Startups, agencias, migraciones rápidas. |
| **Angular** | Google | "Baterías incluidas". Todo viene de caja (Router, HTTP). | Alta. TypeScript obligatorio. Complejo. | Bancos, Enterprise, equipos gigantes. |
| **Svelte** | Rich Harris | "El compilador". No envía framework al navegador. | Media. Sintaxis muy limpia. | Apps de alto rendimiento, webs interactivas. |

### 2.3 Build Tools (Los Empaquetadores)
El navegador no entiende archivos `.vue` o `.jsx` o TypeScript. Alguien tiene que traducirlos.
*   **Webpack:** El rey antiguo. Poderoso pero configuración infernal.
*   **Vite (El Nuevo Estándar):** Creado por el autor de Vue. Es instantáneo. Usa ES Modules nativos. Si empiezas hoy, usa Vite.
*   **Babel:** El traductor. Convierte código JS moderno (2025) a código que entienda Internet Explorer (si es que alguien lo usa).

### 2.4 La Guerra del CSS: Tailwind vs Bootstrap
No es cuestión de gustos, es cuestión de arquitectura.

| Característica | Bootstrap (El Clásico) | Tailwind CSS (La Revolución) |
| :--- | :--- | :--- |
| **Filosofía** | Componentes listos (`btn-primary`). | Utilidades atómicas (`bg-blue-500 p-4`). |
| **HTML** | Limpio (`class="card"`). | Verboso (`class="flex p-4 bg-white rounded shadow"`). |
| **Personalización** | Difícil (sobreescribir SASS). | Infinita (configuración JS). |
| **Tamaño Final** | ~150kb (si no purgas). | ~10kb (purga automática). |
| **Veredicto** | Úsalo si no tienes diseñador y quieres algo rápido. | Úsalo si quieres control total y rendimiento. |

### 2.5 Gestión del Estado (State Management)
El problema eterno: "¿Cómo le paso datos del componente A al componente Z sin pasar por todos los del medio (Prop Drilling)?"
*   **Context API (Nativo de React):** Bueno para datos simples (Usuario logueado, Tema Oscuro/Claro).
*   **Redux (El Gigante):** Potente pero muy complejo (Boilerplate). Un solo "Store" inmutable. Ideal para apps financieras o muy grandes.
*   **Zustand / Jotai:** La nueva ola. Simples, minimalistas y sin tanto código.
*   **TanStack Query (React Query):** No es gestión de estado global, es gestión de estado **asíncrono** (Servidor). Elimina el 90% del uso de useEffect para fetch de datos.

## 3. El Backend Moderno: Motores de Lógica

Aquí ocurre la magia: Pagos, Base de Datos, Autenticación, IA.

### 3.1 Node.js (JavaScript en el Servidor)
*   *Filosofía:* Non-blocking I/O. Un solo hilo que nunca se detiene.
*   *Ventaja:* "Isomorfismo". Usas el mismo lenguaje (JS) en Frontend y Backend. Compartes código.
*   *Uso:* Apps en tiempo real (Chats, Uber), APIs REST, Streaming (Netflix usa Node).

### 3.2 Python (Django / FastAPI)
*   *Filosofía:* "Baterías incluidas" (Django) o "Velocidad pura" (FastAPI).
*   *Ventaja:* El lenguaje de la Inteligencia Artificial. Librerías infinitas.
*   *Uso:* Data Science, Instagram (Django), Pinterest, ML Integrations.

### 3.3 Go (Golang)
*   *Filosofía:* Creado por Google para reemplazar a C++. Simple, compilado, concurrencia nativa (Goroutines).
*   *Ventaja:* Rendimiento brutal con sintaxis fácil.
*   *Uso:* Microservicios de alto tráfico (Uber migró de Node a Go), Docker y Kubernetes están hechos en Go.

### 3.4 Java (Spring Boot) / C# (.NET)
*   *Filosofía:* Robustez, Tipado estático fuerte, Entorno corporativo.
*   *Ventaja:* Estabilidad y ecosistema maduro.
*   *Uso:* Bancos, Aseguradoras, Gobiernos. Software que debe durar 20 años.

### 3.5 PHP (Laravel)
*   *Filosofía:* "La web es su hogar".
*   *Realidad:* Mueve el 70% de la web (WordPress). Laravel lo modernizó y es una joya de productividad.
*   *Uso:* Freelancing, Agencias, E-commerce rápido.

## 4. Bases de Datos: El Oro del Siglo XXI

No existe una "mejor base de datos". Existe la adecuada para tus datos.

### 4.1 Relacionales (SQL - ACID)
Datos estructurados, tablas fijas, relaciones estrictas.
*   **PostgreSQL:** El estándar open source moderno. Soporta JSON también.
*   **MySQL / MariaDB:** El clásico. Rápido para lecturas.

### 4.2 No Relacionales (NoSQL - BASE)
Escalabilidad horizontal, esquemas flexibles.
*   **Documental (MongoDB):** Guardas JSONs. Ideal para catálogos de productos variados.
*   **Key-Value (Redis):** RAM pura. Caché, sesiones, colas.
*   **Grafos (Neo4j):** "¿Quién es amigo del amigo de mi amigo?". Redes sociales, recomendaciones (Como el motor de Netflix).
*   **Time-Series (InfluxDB):** Datos de sensores IoT, logs, métricas financieras.

## 5. Cloud Computing y DevOps: La Infraestructura Moderna

"El código que funciona en tu máquina no sirve si no funciona en producción".

### 5.1 Los Tres Grandes (Cloud Providers)
Ya nadie compra servidores físicos (On-Premise) a menos que sea un banco paranoico.
1.  **AWS (Amazon Web Services):** El pionero y líder (33% del mercado). Complejo pero omnipresente.
2.  **Microsoft Azure:** El favorito de las empresas que ya usan Windows/Office. Crecimiento enorme.
3.  **Google Cloud (GCP):** El favorito para Big Data y Kubernetes.

### 5.2 Contenedores (Docker)
Antes, enviabas el código y rezabas para que el servidor tuviera la misma versión de Python que tú.
*   **Docker:** Empaqueta tu código + librerías + sistema operativo en una "caja" (Container).
*   **Promesa:** "Si corre en mi máquina, corre en cualquier lado".

### 5.3 Orquestación (Kubernetes / K8s)
Docker maneja 1 contenedor. Kubernetes maneja 10,000 contenedores.
*   *Función:* Si un contenedor muere, K8s crea otro automáticamente. Si hay mucho tráfico, K8s crea 50 copias más.
*   *Origen:* Donado por Google (basado en su sistema interno Borg).

### 5.4 CI/CD (Continuous Integration / Continuous Deployment)
Automatización del despliegue.
*   **CI (Integración):** GitHub Actions detecta que subiste código, corre los tests automáticos. Si fallan, te avisa.
*   **CD (Despliegue):** Si los tests pasan, el código se sube automáticamente a producción sin intervención humana.
*   *Herramientas:* GitHub Actions, Jenkins, CircleCI.

## 6. Tecnologías de Comunicación (APIs)

No basta con HTTP GET/POST. Hay formas más sofisticadas de hablar.

### 6.1 REST (Representational State Transfer)
El estándar de facto.
*   *Formato:* JSON.
*   *Verbos:* GET, POST, PUT, DELETE.
*   *Desventaja:* **Over-fetching**. Pides `/users/1` y te devuelve 50 campos, aunque solo querías el nombre.

### 6.2 GraphQL (La Revolución de Facebook)
Un lenguaje de consulta para tu API.
*   *Filosofía:* "Pide exactamente lo que necesitas, nada más".
*   *Ejemplo Query:*
    ```graphql
    {
      user(id: "1") {
        name
        avatar
      }
    }
    ```
*   *Ventaja:* Evita el over-fetching. Ideal para móviles con pocos datos.
*   *Desventaja:* Complejidad de caché y seguridad en el backend.

### 6.3 gRPC (Google Remote Procedure Call)
Alto rendimiento entre microservicios.
*   *Formato:* **Protobuf** (Binario, no texto). Mucho más ligero que JSON.
*   *Protocolo:* HTTP/2 nativo.
*   *Uso:* Comunicación interna entre microservicios (Backend a Backend). No suele usarse directamente desde el navegador.

### 6.4 WebSockets (Real-Time)
Comunicación bidireccional persistente.
*   *Diferencia:* En HTTP, el cliente siempre inicia. En WebSockets, el servidor puede enviar datos al cliente sin que este pregunte.
*   *Uso:* Chats, Juegos Multijugador, Bolsa de Valores en vivo.

## 7. Seguridad y Autenticación: El Guardián

"La seguridad no es una característica, es un requisito básico".

### 7.1 Métodos de Autenticación
1.  **Session-Based (Clásico):** El servidor crea una "sesión" en memoria y le da una cookie al navegador.
    *   *Problema:* Difícil de escalar horizontalmente (¿qué pasa si el usuario cae en otro servidor que no tiene la sesión?).
2.  **Token-Based (JWT - JSON Web Tokens):** El estándar moderno.
    *   *Funcionamiento:* El servidor te da un "gafete" firmado criptográficamente. El servidor no guarda nada en memoria. Solo verifica la firma.
    *   *Ventaja:* Stateless. Escala infinito.
3.  **OAuth 2.0 / OIDC:** "Inicia sesión con Google/Facebook".
    *   Delegas la seguridad a un experto. No toques las contraseñas de los usuarios si puedes evitarlo.

### 7.2 HTTPS y Certificados SSL/TLS
Hoy en día, Chrome marca como "No Seguro" cualquier sitio HTTP.
*   **Let's Encrypt:** Revolucionó la web dando certificados SSL gratuitos y automáticos. Ya no hay excusa para no usar HTTPS.

## 8. Testing: Calidad de Software

Si no está probado, está roto.

### 8.1 Pirámide de Testing
1.  **Unit Tests (Base):** Prueban una función aislada (`sumar(2,2)`). Rápidos y baratos. (Jest, Vitest).
2.  **Integration Tests (Centro):** Prueban que la Base de Datos hable bien con la API.
3.  **E2E (End-to-End) (Punta):** Un robot abre el navegador real, hace clic en "Comprar" y verifica que salga el recibo. Lentos y caros pero simulan al usuario real. (Cypress, Playwright).

## 9. Tendencias Emergentes (El Futuro)

### 9.1 WebAssembly (Wasm)
Ejecutar código binario de C++, Rust o Go en el navegador a velocidad casi nativa.
*   *Uso:* Photoshop Web, Figma, editores de video en el navegador, juegos 3D.
*   *Revolución:* Rompe el monopolio de JavaScript en el navegador.

### 9.2 Low-Code / No-Code
Herramientas como Webflow, Bubble o OutSystems.
*   *Realidad:* Permiten crear aplicaciones simples 10x más rápido.
*   *Amenaza:* ¿Reemplazarán a los programadores? No, pero eliminarán el trabajo repetitivo y aburrido (CRUDs básicos).

### 9.3 AI-Assisted Coding
GitHub Copilot, Cursor, ChatGPT.
*   *Cambio de Paradigma:* El programador pasa de ser un "escritor de código" a un "editor y arquitecto de código".
*   *Peligro:* Generar código que no entiendes. Si hay un bug, no sabrás arreglarlo.

## 10. La Piedra Rosetta del Backend: 5 Lenguajes, 1 Misión

Para entender realmente las diferencias, no leas teoría. Lee código.
Vamos a crear la misma **API REST** (`GET /hello`) que devuelve `{"message": "Hello World"}` en los 5 lenguajes más importantes.

### 10.1 Node.js (con Express)
*   **Veredicto:** Conciso, asíncrono, familiar si vienes del Frontend.
```javascript
const express = require('express');
const app = express();

app.get('/hello', (req, res) => {
    res.json({ message: "Hello World from Node.js" });
});

app.listen(3000, () => console.log('Server on port 3000'));
```

### 10.2 Python (con FastAPI)
*   **Veredicto:** Elegante, tipado moderno, documentación automática (Swagger) gratis.
```python
from fastapi import FastAPI
import uvicorn

app = FastAPI()

@app.get("/hello")
def read_root():
    return {"message": "Hello World from Python"}

if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```

### 10.3 Go (Golang - Librería Estándar)
*   **Veredicto:** Verboso pero explícito. Sin frameworks pesados. Compila a binario. Rendimiento brutal.
```go
package main

import (
    "encoding/json"
    "net/http"
)

type Response struct {
    Message string `json:"message"`
}

func helloHandler(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    response := Response{Message: "Hello World from Go"}
    json.NewEncoder(w).Encode(response)
}

func main() {
    http.HandleFunc("/hello", helloHandler)
    http.ListenAndServe(":8080", nil)
}
```

### 10.4 Java (con Spring Boot)
*   **Veredicto:** Mucho "boilerplate" (código repetitivo), anotaciones mágicas, orientado a objetos puro. Robusto.
```java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
import java.util.HashMap;
import java.util.Map;

@SpringBootApplication
@RestController
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

    @GetMapping("/hello")
    public Map<String, String> hello() {
        HashMap<String, String> map = new HashMap<>();
        map.put("message", "Hello World from Java");
        return map;
    }
}
```

### 10.5 PHP (Vanilla Moderno)
*   **Veredicto:** El más simple de desplegar (solo sube el archivo). Sin servidor de aplicaciones complejo.
```php
<?php
// index.php
header('Content-Type: application/json');

$response = [
    "message" => "Hello World from PHP"
];

echo json_encode($response);
?>
```

### Análisis Comparativo Final
1.  **Líneas de Código:** Python y Node ganan por goleada. Java pierde.
2.  **Velocidad de Arranque:** Go y PHP son instantáneos. Java tarda segundos.
3.  **Tipado:** Java y Go son estrictos (menos bugs en runtime). Node y Python son dinámicos (riesgo de errores tontos).

## 11. Deep Dive: Estructura Profesional del MERN Stack

Decimos "MERN" muy a la ligera. Así es como se estructura un proyecto real de nivel senior.

### 11.1 Backend (Node/Express): Arquitectura por Capas
Jamás escribas toda la lógica en el archivo `index.js`.
```text
/backend
├── /config         # Variables de entorno, conexión a DB
├── /controllers    # Lógica de los endpoints (req, res)
├── /models         # Esquemas de Mongoose (User, Product)
├── /routes         # Definición de rutas (/api/users, /api/auth)
├── /middleware     # Verificación de JWT, manejo de errores
├── /utils          # Funciones auxiliares (enviar email, calcular fecha)
└── server.js       # Punto de entrada
```

### 11.2 Frontend (React): Patrón de Características (Feature-Based)
Olvida agrupar por "tipos" (todos los componentes juntos). Agrupa por "funcionalidad".
```text
/frontend/src
├── /assets         # Imágenes, fuentes
├── /components     # UI Genérica (Botones, Inputs, Modales reutilizables)
├── /features       # Lógica de negocio encapsulada
│   ├── /auth       # Login, Register, ForgotPassword
│   │   ├── /components
│   │   ├── /hooks  # useAuth, useLogin
│   │   └── /api    # authService.js
│   └── /products   # ProductList, ProductDetail
├── /layouts        # DashboardLayout, AuthLayout
├── /pages          # Vistas completas que unen todo
├── /routes         # AppRouter, PrivateRoute
└── /services       # Configuración de Axios
```

### 11.3 El Flujo de Datos (The Data Flow)
1.  **Frontend:** Usuario llena formulario en `LoginPage.jsx`.
2.  **Frontend:** `authService.js` envía POST a `https://api/login`.
3.  **Backend:** `authRoutes.js` recibe la petición.
4.  **Backend:** `authMiddleware.js` valida que el body tenga email/password.
5.  **Backend:** `authController.js` busca en `UserModel.js`.
6.  **Backend:** Si es correcto, genera un JWT y responde 200 OK.
7.  **Frontend:** Guarda el JWT en `localStorage` o Cookies.

## 12. Modelado de Datos: SQL vs NoSQL (Caso Práctico)

¿Cómo guardamos una factura en ambos mundos?

### 12.1 En SQL (PostgreSQL - Normalizado)
Necesitamos 3 tablas separadas para evitar redundancia.

**Tabla: Users**
| id | name | email |
| :--- | :--- | :--- |
| 1 | Juan | juan@mail.com |

**Tabla: Orders**
| id | user_id | date | total |
| :--- | :--- | :--- | :--- |
| 100 | 1 | 2024-01-20 | 500.00 |

**Tabla: Order_Items** (Tabla pivote)
| id | order_id | product_name | qty | price |
| :--- | :--- | :--- | :--- | :--- |
| 50 | 100 | Laptop | 1 | 450 |
| 51 | 100 | Mouse | 1 | 50 |

*   **Consulta:** `JOIN Users ON Orders.user_id = Users.id JOIN Order_Items...`

### 12.2 En NoSQL (MongoDB - Documento Embebido)
Todo vive junto. Lectura atómica ultra rápida.
```json
// Colección: Orders
{
  "_id": "507f1f77bcf86cd799439011",
  "date": "2024-01-20",
  "total": 500.00,
  "user": {
    "name": "Juan",
    "email": "juan@mail.com"
  },
  "items": [
    { "product": "Laptop", "qty": 1, "price": 450 },
    { "product": "Mouse",  "qty": 1, "price": 50 }
  ]
}
```
*   **Dilema:** Si Juan cambia su email, en NoSQL tienes que actualizarlo en TODAS sus órdenes pasadas (o dejarlo desactualizado). En SQL solo lo cambias en la tabla `Users`.

## 13. Rendimiento Web y Core Web Vitals

No importa qué stack uses si tu web tarda 10 segundos en cargar. Google te penalizará.

### 13.1 Métricas Críticas (Core Web Vitals de Google)
Google mide 3 cosas para decidir si rankea tu web arriba o abajo:
1.  **LCP (Largest Contentful Paint):** Velocidad de Carga.
    *   *Meta:* < 2.5 segundos.
    *   *Lo que cuenta:* Cuánto tarda en aparecer el elemento más grande (imagen principal o título).
2.  **INP (Interaction to Next Paint):** Interactividad.
    *   *Meta:* < 200 milisegundos.
    *   *Lo que cuenta:* Si haces clic en un botón, ¿cuánto tarda el navegador en pintar el siguiente frame? (Sustituyó a FID).
3.  **CLS (Cumulative Layout Shift):** Estabilidad Visual.
    *   *Meta:* < 0.1.
    *   *Lo que cuenta:* ¿Se mueven las cosas solas mientras leo? (Ej. Un banner publicitario carga tarde y empuja todo el texto hacia abajo).

### 13.2 Lighthouse
La herramienta estándar de auditoría (viene en Chrome DevTools).
Mide:
*   Performance (Velocidad).
*   Accessibility (¿Pueden usarlo ciegos?).
*   Best Practices (¿Usas HTTPS? ¿Imágenes optimizadas?).
*   SEO (¿Tienes meta tags?).

### 13.3 SSR vs SSG vs ISR (Deep Dive Next.js)
Entender esto te pone en el top 10% de desarrolladores.
*   **SSR (Server Side Rendering):** La página se genera en el servidor en CADA petición. (Bien para SEO, Lento para el server).
*   **SSG (Static Site Generation):** La página se genera UNA VEZ al construir (Build time). Ultra rápido. (Bien para Blogs, Landing Pages).
*   **ISR (Incremental Static Regeneration):** Lo mejor de ambos mundos. La página es estática, pero se regenera sola cada X segundos si hay nuevos datos.

## 14. Git Moderno: Más allá del Commit

Saber `git add .` no es suficiente.

### 14.1 Git Flow vs Trunk Based
*   **Git Flow:** Ramas eternas (`develop`, `release`). Complejo. Bueno para software empaquetado (versiones 1.0, 2.0).
*   **Trunk Based Development:** Todos hacen push a `main` todos los días. Requiere Tests automáticos potentes. Es lo que usan Google y Facebook.

### 14.2 Conventional Commits
Escribe mensajes que las máquinas entiendan.
*   `feat: add new login button` (Nueva funcionalidad)
*   `fix: resolve crash on IOS` (Arreglo de bug)
*   `docs: update readme` (Documentación)
*   **Ventaja:** Generan el CHANGELOG automáticamente.

## 15. Tu Entorno de Desarrollo (El Dojo del Programador)

No puedes ser un samurai con una espada de madera. Necesitas herramientas profesionales.

### 11.1 VS Code: Configuración Pro
Instala estas extensiones Sí o SÍ:
1.  **ESLint / Prettier:** Formato automático. Se acabó el discutir si van espacios o tabs.
2.  **GitLens:** ¿Quién escribió esta línea de código hace 3 meses? GitLens te lo dice.
3.  **Live Server:** Para ver tus cambios de HTML al instante.
4.  **Thunder Client:** Como Postman, pero dentro de VS Code. Para probar tus APIs.
5.  **Material Icon Theme:** Porque los iconos bonitos ayudan a identificar archivos rápido.

### 11.2 La Terminal (Tu mejor amiga)
Deja de usar el ratón. Aprende estos comandos básicos de Unix (Mac/Linux/Git Bash):
*   `ls -la`: Listar todo (incluso ocultos).
*   `cd ..`: Subir un nivel.
*   `mkdir proyecto`: Crear carpeta.
*   `touch index.js`: Crear archivo.
*   `rm -rf node_modules`: Borrar la carpeta más pesada del universo (con cuidado).

## 16. Ejercicios y Retos Técnicos

### Reto 1: "Investigación Forense"
Ve a `facebook.com` o `amazon.com`.
1.  Abre las DevTools (F12) -> Red (Network).
2.  Filtra por "XHR" o "Fetch".
3.  Navega un poco.
4.  **Misión:** Encuentra una petición que devuelva un JSON. Copia ese JSON. ¿Qué estructura tiene? ¿Qué servidor web usan (mira los Headers)?

### Reto 2: "El Políglota"

## 17. Glosario Técnico de Tecnologías

*   **Babel:** Transpilador de JavaScript que convierte código moderno ES6+ en código compatible con navegadores antiguos.
*   **CLI (Command Line Interface):** Interfaz donde interactúas con la computadora mediante texto en lugar de gráficos.
*   **Compilador vs Intérprete:** El compilador (C++, Go) traduce todo el programa a binario antes de correr. El intérprete (Python, JS) lee y ejecuta línea por línea.
*   **Dependency Injection:** Patrón de diseño donde las dependencias de una clase se pasan desde fuera en lugar de crearse dentro. Muy usado en Angular y Spring.
*   **DOM (Document Object Model):** Representación en árbol que el navegador hace de tu HTML. JavaScript manipula el DOM, no el archivo HTML.
*   **EcmaScript (ES):** El estándar oficial que define cómo funciona JavaScript. ES6 (2015) fue el cambio más grande.
*   **Full Stack:** Desarrollador capaz de trabajar en todas las capas (Frontend, Backend, DB, DevOps).
*   **Git:** Sistema de control de versiones distribuido.
*   **HMR (Hot Module Replacement):** Tecnología de Vite/Webpack que actualiza el módulo que cambiaste en el navegador sin recargar toda la página.
*   **Hydration:** Proceso donde JavaScript se "conecta" al HTML estático que vino del servidor para hacerlo interactivo.
*   **Isomorfismo:** Capacidad de ejecutar el mismo código (usualmente JS) en cliente y servidor.
*   **LTS (Long Term Support):** Versiones de software (Node.js, Ubuntu) que garantizan soporte y parches de seguridad por años. Usa siempre LTS en producción.
*   **Transpilación:** Traducir código de un lenguaje a otro de similar nivel de abstracción (ej. TypeScript a JavaScript).
*   **Webhook:** Una "llamada telefónica" inversa. En lugar de que tú preguntes a Stripe "ya pagó el usuario?", Stripe te llama a ti (a tu URL) cuando paga.
