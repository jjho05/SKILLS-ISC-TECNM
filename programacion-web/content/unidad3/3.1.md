# 3.1. Introducción al Lenguaje JavaScript

JavaScript (JS) es el lenguaje de programación de la Web. Originalmente diseñado para agregar interactividad simple a las páginas, ha evolucionado hasta convertirse en un ecosistema masivo que corre en servidores (Node.js), robots, cohetes (SpaceX usa JS en interfaces) y dispositivos móviles.

Este documento cubre desde los fundamentos históricos hasta las entrañas del motor V8.

---

## 1. Historia: De Mocha a ESNext

### 1.1 El Nacimiento (1995)
Brendan Eich creó la primera versión de JavaScript en **10 días** en Mayo de 1995, mientras trabajaba en Netscape.
*   **Nombre Original:** Mocha.
*   **Nombre Beta:** LiveScript.
*   **Nombre Marketing:** JavaScript (para colgarse de la fama de Java, aunque NO tienen relación).

### 1.2 La Guerra de los Navegadores y ECMA (1996-1997)
Microsoft clonó JS y lo llamó JScript para Internet Explorer.
Para evitar la fragmentación, Netscape llevó el lenguaje a **ECMA International** (European Computer Manufacturers Association) para estandarizarlo.
*   **Resultado:** El estándar oficial se llama **ECMAScript**. JavaScript es la implementación comercial.

### 1.3 La Edad Oscura (ES3 - 1999 a 2009)
Durante 10 años, el lenguaje no cambió. Internet Explorer 6 dominaba y frenaba la innovación.
Nació **AJAX** (2005) gracias a Google Maps, demostrando que la web podía ser una aplicación real.

### 1.4 El Renacimiento (ES5 - 2009 y ES6/ES2015)
*   **ES5 (2009):** `forEach`, `map`, `filter`, `JSON`, `strict mode`.
*   **ES6 (2015):** El cambio más grande de la historia. `let`, `const`, `Clases`, `Módulos`, `Promesas`, `Arrow Functions`.
*   **ESNext (2016-Hoy):** Actualizaciones anuales pequeñas (ES2016, ES2017...).

## 2. El Motor JavaScript (V8 Engine)

El navegador no "lee" JS línea por línea. Lo **compila**.

### 2.1 JIT Compilation (Just-In-Time)
El motor V8 (Chrome/Node) usa un compilador JIT.
1.  **Parser:** Convierte tu código en un AST (Abstract Syntax Tree).
2.  **Ignition (Intérprete):** Ejecuta el Bytecode rápidamente.
3.  **TurboFan (Optimizador):** Observa qué funciones se usan mucho ("Hot functions") y las recompila a Código Máquina optimizado para la CPU.

### 2.2 Memory Heap y Call Stack
*   **Memory Heap:** Donde se asignan las variables y objetos. (Espacio desordenado).
*   **Call Stack:** Donde se apilan las funciones a ejecutar. (LIFO: Last In, First Out).
    *   JS es **Single Threaded**: Solo tiene un Call Stack. Solo puede hacer una cosa a la vez.

## 3. Variables y Ámbito (Scope)

En JS moderno, `var` está muerto. Larga vida a `let` y `const`.

### 3.1 `var` (El abuelo problemático)
*   **Function Scope:** Solo respeta las funciones, no los bloques (`if`, `for`).
*   **Hoisting:** Se "eleva" al inicio, pero con valor `undefined`.
*   **Re-declarable:** Puedes declarar `var x` mil veces sin error.

```javascript
if (true) {
    var x = 10;
}
console.log(x); // 10 (¡El horror! Se escapó del if)
```

### 3.2 `let` (Variable reasignable)
*   **Block Scope:** Respeta `{ }`.
*   **No Hoisting (TDZ):** Temporal Dead Zone. Si la usas antes de declarar, falla.

```javascript
if (true) {
    let y = 20;
}
console.log(y); // ReferenceError: y is not defined (Correcto)
```

### 3.3 `const` (Constante... más o menos)
*   **Block Scope.**
*   Debes inicializarla al declarar.
*   **Referencia Inmutable:** No puedes reasignar el identificador, PERO si es un objeto, puedes cambiar sus propiedades.

```javascript
const user = { name: "Jesús" };
user.name = "Paco"; // VÁLIDO. Mutaste el objeto, no la referencia.
// user = {}; // ERROR. Reasignación prohibida.
```

**Regla de Oro:** Usa `const` por defecto. Usa `let` solo si sabes que el valor va a cambiar (ej. un contador). Nunca uses `var`.

## 4. Tipos de Datos (Primitivos vs Referencia)

JS es de tipado dinámico.

### 4.1 Primitivos (Inmutables)
Se pasan por **valor**.
1.  **String:** `'Hola'`
2.  **Number:** `42`, `3.14`, `NaN`, `Infinity`.
3.  **Boolean:** `true`, `false`.
4.  **Null:** Valor nulo intencional. (Bug histórico: `typeof null` es `'object'`).
5.  **Undefined:** Valor no asignado.
6.  **Symbol** (ES6): Identificador único.
7.  **BigInt** (ES2020): Enteros arbitrariamente grandes (`9007199254740991n`).

### 4.2 Objetos (Referencia)
Se pasan por **referencia**.
*   Object `{}`
*   Array `[]`
*   Function `function() {}`
*   Date, Map, Set, Promise...

```javascript
let a = 10;
let b = a;
a = 20;
console.log(b); // 10 (Copia independiente)

let obj1 = { valor: 10 };
let obj2 = obj1;
obj1.valor = 20;
console.log(obj2.valor); // 20 (Apuntan al mismo lugar en memoria)
```

## 5. Coerción de Tipos: El lado oscuro de JS

JS intenta ser "amigable" y convertir tipos automáticamente. A veces es útil, a veces es el infierno.

### 5.1 Coerción Implícita (La Magia Negra)
El motor convierte los tipos para que la operación "funcione".

*   **String Number:**
    ```javascript
    '5' - 1 // 4 (El - solo funciona con números, convierte '5' a 5)
    '5' + 1 // '51' (El + sirve para concatenar, prefiere string)
    ```

*   **Boolean:**
    ```javascript
    true + 1 // 2 (true se convierte en 1)
    false + 1 // 1 (false se convierte en 0)
    ```

*   **Null/Undefined:**
    ```javascript
    10 + null // 10 (null -> 0)
    10 + undefined // NaN (undefined no es un número válido)
    ```

### 5.2 Truthy y Falsy
En un contexto booleano (`if`), todo valor es verdadero EXCEPTO estos 6 **Falsy values**:
1.  `false`
2.  `0` (y `-0`)
3.  `""` (String vacío)
4.  `null`
5.  `undefined`
6.  `NaN`

Todo lo demás es **Truthy** (incluyendo `[]`, `{}`, `'0'`, `'false'`).

### 5.3 Igualdad: `==` vs `===`
*   `==` (Loose Equality): Permite coerción. `'5' == 5` es `true`. **MALA PRÁCTICA.**
*   `===` (Strict Equality): Compara tipo Y valor. `'5' === 5` es `false`. **SIEMPRE USA ESTE.**
*   `Object.is(a, b)`: Para casos extremos (`NaN === NaN` es false, pero `Object.is(NaN, NaN)` es true).

## 6. Funciones: Ciudadanos de Primera Clase

En JS, las funciones son objetos. Puedes pasarlas como argumentos, retornarlas, y asignarlas a variables.

### 6.1 Function Declaration (Con Hoisting)
Se pueden llamar antes de definirlas.
```javascript
saludar(); // Funciona
function saludar() { return "Hola"; }
```

### 6.2 Function Expression (Sin Hoisting)
Son variables.
```javascript
const sumar = function(a, b) { return a + b; };
// sumar(1, 2);
```

### 6.3 Arrow Functions (ES6)
Sintaxis corta y NO tienen su propio `this`.
```javascript
const cuadrado = x => x * x;
const sumar = (a, b) => {
    return a + b;
};
// Return implícito si no hay llaves:
const flecha = () => "Soy un one-liner";
```

### 6.4 IIFE (Immediately Invoked Function Expression)
Patrón antiguo para encapsular variables antes de los módulos.
```javascript
(function() {
    var secreto = "No soy global";
})();
```

## 7. Scope y Hoisting a Fondo

### 7.1 Scope Chain (Cadena de alcance)
Si una variable no está en mi función, JS busca en el padre. Y luego en el abuelo. Hasta llegar al Global Scope.
Esto se define **lexicalmente** (donde escribiste el código), no donde lo llamas.

### 7.2 El Mito del Hoisting
Se dice que JS "mueve" las declaraciones arriba.
En realidad, el motor hace una primera pasada (memoria) y reserva el espacio.
*   `var`: Se inicializa con `undefined`.
*   `let/const`: Se queda en **TDZ** (Zona Muerta Temporal) sin inicializar.
*   `function`: Se guarda completa en memoria.

## 8. Closures (Clausuras): El concepto más difícil

Una Closure es una función que **recuerda** las variables de su entorno exterior, incluso después de que la función exterior haya terminado de ejecutarse.

### 8.1 Anatomía de una Closure
```javascript
function crearContador() {
    let cuenta = 0; // Variable privada
    
    return function() {
        cuenta++;
        return cuenta;
    };
}

const miContador = crearContador();
console.log(miContador()); // 1
console.log(miContador()); // 2
console.log(cuenta); // Error: cuenta is not defined
```

### 8.2 ¿Para qué sirven?
1.  **Datos Privados:** Simular variables privadas (antes de que existieran clases con `#private`).
2.  **Factory Functions:** Funciones que crean otras funciones configuradas (`crearMultiplicador(5)`).
3.  **Event Listeners y Callbacks:** Mantener estado en manejadores de eventos.

## 9. La palabra clave `this`

`this` no se refiere a la función en sí, ni a su scope. Se refiere a **cómo se llamó la función**.

### 9.1 Las 4 Reglas de `this`
1.  **Default Binding:** En modo estricto, `undefined`. En modo normal, `window`.
    ```javascript
    function hola() { console.log(this); }
    hola(); // Window
    ```
2.  **Implicit Binding:** El objeto antes del punto.
    ```javascript
    const obj = {
        nombre: "Jesús",
        hablar() { console.log(this.nombre); }
    };
    obj.hablar(); // "Jesús"
    ```
3.  **Explicit Binding:** `call`, `apply`, `bind`.
    ```javascript
    function saludar() { console.log(this.nombre); }
    const usuario = { nombre: "Ana" };
    saludar.call(usuario); // "Ana"
    ```
4.  **New Binding:** Con el constructor `new`.
    ```javascript
    const auto = new Carro(); // this = nuevo objeto vacío
    ```

### 9.2 El truco de la Arrow Function
Las Arrow Functions **NO** tienen `this`. Toman el `this` de su entorno padre (Lexical `this`).
Por eso son ideales para React y Callbacks.

## 10. Modern JavaScript (ES6+ Cheatsheet)

Si no usas esto en 2025, escribes código legacy.

### 10.1 Template Literals
Adiós a `'Hola ' + nombre + '!'`.
```javascript
const mensaje = `Hola ${nombre}, son las ${Date.now()}`;
// Soporta multilínea
const html = `
    <div>
        <h1>Título</h1>
    </div>
`;
```

### 10.2 Destructuring (Desestructuración)
Extraer datos de arrays u objetos.
```javascript
// Objetos
const user = { id: 1, name: "Admin", role: "Super" };
const { name, role } = user;

// Arrays
const coords = [10, 20];
const [x, y] = coords;
```

### 10.3 Spread Operator (`...`)
Expandir elementos.
```javascript
const frutas = ["Manzana", "Pera"];
const copia = [...frutas]; // Copia real, no referencia
const nuevoArray = [...frutas, "Uva"];

const obj1 = { a: 1 };
const obj2 = { ...obj1, b: 2 }; // Merge de objetos
```

### 10.4 Módulos (ES Modules)
El sistema oficial de JS.
```javascript
// archivo.js
export const pi = 3.14;
export default function sumar(a, b) { return a + b; }

// main.js
import sumar, { pi } from './archivo.js';
```

## 11. El Event Loop: El Corazón Asíncrono

JavaScript es **Single Threaded** (un solo hilo). ¿Cómo puede hacer peticiones a servidores sin congelar la pantalla?
Gracias al **Event Loop**.

### 11.1 Componentes del Runtime
1.  **Call Stack:** Donde se ejecuta el código JS (síncrono).
2.  **Web APIs:** APIs del navegador (DOM, `setTimeout`, `fetch`, `geolocation`). Estas corren en *hilos separados* del navegador (C++).
3.  **Callback Queue (Task Queue):** Cola de espera para `setTimeout`.
4.  **Microtask Queue:** Cola VIP para `Promises`. Tiene mayor prioridad.

### 11.2 El Ciclo Infinito
El Event Loop hace una sola pregunta 60 veces por segundo:
*"¿Está vacío el Call Stack? Si sí, muevo cosas de la Queue al Stack."*

```javascript
console.log('1');

setTimeout(() => {
    console.log('2');
}, 0);

Promise.resolve().then(() => {
    console.log('3');
});

console.log('4');

// Orden real: 1 -> 4 -> 3 -> 2
// Explicación:
// 1 y 4 son síncronos (Call Stack).
// 3 es Microtask (Promise) -> Se ejecuta inmediatamente después del Stack.
// 2 es Macrotask (setTimeout) -> Se ejecuta al final.
```

## 12. Prototipos y Herencia (La verdad sobre las Clases)

En JS las `class` son solo "azúcar sintáctica". Bajo la capucha, todo son objetos y prototipos.
Todo objeto tiene una propiedad interna llamada `[[Prototype]]` (o `__proto__` en navegadores viejos) que apunta a otro objeto.

### 12.1 La Cadena de Prototipos
Si buscas `usuario.apellidos` y no existe en `usuario`, JS busca en su prototipo. Y luego en el prototipo del prototipo.
Hasta llegar a `Object.prototype` (el Adán de todos los objetos) y finalmente `null`.

```javascript
const animal = { vivo: true };
const perro = Object.create(animal); // perro hereda de animal
perro.ladrar = true;

console.log(perro.ladrar); // true (Propio)
console.log(perro.vivo);   // true (Heredado de animal)
console.log(perro.alas);   // undefined (Llegó al final y no encontró nada)
```

## 13. Strict Mode (`'use strict'`)

Una forma de optar por una variante más limpia y segura de JS.
Se activa poniendo `'use strict';` al inicio del archivo o función.

### 13.1 ¿Qué arregla?
1.  **Variables globales:** Error si asignas `x = 10` sin `var/let/const`. (Antes creaba una global por error).
2.  **`this`:** En funciones sueltas, `this` es `undefined` en lugar de `window`.
3.  **Duplicados:** Prohíbe parámetros duplicados `function(a, a)`.
4.  **Palabras reservadas:** Reserva palabras para el futuro (`implements`, `interface`, `package`).

**Nota:** Los Módulos ES6 (`import/export`) y las Clases tienen `'use strict'` activado automáticamente.

## 14. Sistemas de Módulos (La Historia)

Antes de ES6 (2015), JS no tenía módulos. Usábamos `<script>` globales y rezábamos.

### 14.1 CommonJS (CJS) - El estándar de Node.js
Nació para el servidor. Es **síncrono**.
```javascript
// Exportar
module.exports = { sumar };

// Importar
const { sumar } = require('./math');
```
*   **Problema:** No funciona en navegadores nativamente (requiere bundlers como Webpack).

### 14.2 ES Modules (ESM) - El estándar de la Web
Nativo, asíncrono y estático (permite Tree Shaking).
```javascript
// Exportar
export const sumar = (a, b) => a + b;

// Importar
import { sumar } from './math.js';
```
*   **Nota:** En Node.js, para usar ESM debes poner `"type": "module"` en tu `package.json` o usar la extensión `.mjs`.

## 15. Manejo de Errores (Error Handling)

JS explota si no manejas los errores.

### 15.1 `try...catch...finally`
```javascript
try {
    // Código peligroso (petición API, JSON.parse)
    const user = JSON.parse('{"mal": json');
} catch (error) {
    // Si falla, cae aquí
    console.error("Falló el parseo:", error.message);
} finally {
    // Se ejecuta SIEMPRE (haya error o no)
    // Ideal para cerrar conexiones o loaders
    console.log("Limpieza terminada");
}
```

### 15.2 Tipos de Errores Nativos
*   `ReferenceError`: Variable no existe (`console.log(x)`).
*   `TypeError`: Ejecutar algo que no es función (`null.f()`).
*   `SyntaxError`: Escribiste mal el código.

## 16. Debugging como un Senior

Deja de usar `console.log('hola')`.

### 16.1 Console API Power Users
*   `console.table(array)`: Muestra datos en tabla excel.
*   `console.time('Loop')` / `console.timeEnd('Loop')`: Mide cuánto tarda un bloque.
*   `console.dir(elemento)`: Muestra el objeto JS de un elemento DOM (no el HTML).
*   `console.trace()`: Muestra el Stack Trace (quién llamó a la función).

### 16.2 La palabra clave `debugger`
Si pones `debugger;` en tu código y tienes DevTools abierto, la ejecución se **pausa** ahí.
Puedes inspeccionar variables paso a paso sin poner breakpoints manuales.

## 17. Gestión de Memoria (Garbage Collection)

JS maneja la memoria por ti, pero puedes causar **Memory Leaks**.

### 17.1 Reachability (Alcanzabilidad)
El Garbage Collector (GC) "Marca y Barre" (Mark and Sweep).
1.  Empieza en la Raíz (Window/Global).
2.  Marca todo lo que está conectado (variables, funciones activas).
3.  Borra de la memoria todo lo que **NO** está marcado.

### 17.2 Fugas de Memoria Comunes
1.  **Variables Globales:** Nunca se borran.
2.  **Intervalos Olvidados:** `setInterval` que nunca haces `clearInterval`.
3.  **Habilitadores de Eventos en nodos borrados:** Si borras un botón del DOM pero tiene un `onclick` apuntando a una función gigante, esa función se queda en memoria.

## 18. Programación Funcional en JS

JS no es Haskell, pero ama la programación funcional.

### 18.1 Funciones Puras
Salida depende SOLO de la entrada. No efectos secundarios.
```javascript
// Pura
const sumar = (a, b) => a + b;

// Impura (Depende de algo externo)
let total = 0;
const agregar = (n) => total += n;
```

### 18.2 Inmutabilidad
No modificar objetos originales. Crear copias.
```javascript
const user = { name: "Jesús" };
// Mal
user.name = "Paco";

// Bien (Nuevo objeto)
const nuevoUser = { ...user, name: "Paco" };
```

### 18.3 Higher Order Functions (HOF)
Funciones que reciben funciones o retornan funciones.
*   `map`, `filter`, `reduce`.
    ```javascript
    const nums = [1, 2, 3];
    const dobles = nums.map(n => n * 2); // [2, 4, 6]
    ```

## 19. Estructuras de Datos Modernas (ES6)

El objeto `{}` no sirve para todo.

### 19.1 `Map` (Diccionario Real)
*   **Claves:** Pueden ser cualquier cosa (¡incluso objetos!), no solo strings.
*   **Orden:** Mantiene el orden de inserción.
    ```javascript
    const mapa = new Map();
    mapa.set('clave', 'valor');
    mapa.set({ id: 1 }, 'Objeto como clave');
    console.log(mapa.size); // 2
    ```

### 19.2 `Set` (Conjunto Único)
Array que no permite duplicados.
```javascript
const unicos = new Set([1, 1, 2, 3]); // {1, 2, 3}
const tieneDos = unicos.has(2); // true (O(1) - Muy rápido)
```

### 19.3 `WeakMap` y `WeakSet`
Sus claves son "débiles". Si nadie más usa el objeto clave, el Garbage Collector lo borra del mapa automáticamente. Ideal para caché en librerías.

## 20. Metaprogramación: `Proxy` y `Reflect`

Magia negra para interceptar operaciones del lenguaje.

### 20.1 Proxy (El Interceptor)
Puedes envolver un objeto y "espiar" cuando alguien lo lee o escribe.
```javascript
const target = { mensaje: "Hola" };

const handler = {
    get(obj, prop) {
        if (prop === 'secreto') return 'shhh';
        return obj[prop];
    },
    set(obj, prop, value) {
        if (typeof value !== 'string') throw new TypeError("Solo texto");
        obj[prop] = value;
        return true;
    }
};

const proxy = new Proxy(target, handler);
console.log(proxy.secreto); // "shhh"
proxy.mensaje = 123; // Error: Solo texto
```
*   **Uso Real:** Así funciona la reactividad de Vue 3.
