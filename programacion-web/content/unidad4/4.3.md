# 4.3. Tratamiento de Formularios

El 90% de los ataques ocurren aquí.
Nunca confíes en lo que envía el usuario. **Nunca.**

---

## 1. Recibiendo Datos (Body Parsers)

Express por defecto **NO** lee el cuerpo de las peticiones POST.
Necesitas enseñarle.

### 1.1 JSON (`application/json`)
Para APIs modernas y SPAs (React, Vue).
```javascript
app.use(express.json()); // El estándar hoy en día

app.post('/api/user', (req, res) => {
    console.log(req.body.username); // "Pedro"
});
```

### 1.2 URL Encoded (`application/x-www-form-urlencoded`)
Para formularios HTML clásicos (`<form method="POST">`).
```javascript
app.use(express.urlencoded({ extended: true }));
```

### 1.3 Límites de Tamaño
Un ataque común es enviar un JSON de 100MB para llenar tu RAM.
```javascript
app.use(express.json({ limit: '10kb' })); // Rechaza si pesa más
```

## 2. Validación de Datos (Schema Validation)

Validar con `if` es sucio y propenso a errores.
Usa **Zod**.

### 2.1 ¿Por qué Zod?
*   Agnóstico (funciona en Node, React, Browsers).
*   Inferencia de Tipos (TypeScript gratis).
*   Sintaxis encadenable.

### 2.2 Ejemplo Real
```javascript
const { z } = require('zod');

const loginSchema = z.object({
    email: z.string().email("Email inválido"), // Valida formato a@b.c
    password: z.string().min(8, "Mínimo 8 caracteres")
});

app.post('/login', (req, res) => {
    const result = loginSchema.safeParse(req.body);
    
    if (!result.success) {
        // Devuelve errores detallados
        return res.status(400).json(result.error.flatten());
    }
    
    // Datos limpios y tipados
    const { email, password } = result.data;
    autenticar(email, password);
});
```

## 3. Sanitización (Limpiando la Basura)

Validar es decir "Esto está mal". Sanitizar es decir "Voy a limpiar esto".

### 3.1 Trim Strings
El usuario escribe " juan@gmail.com " (con espacios).
Zod puede hacerlo por ti:
```javascript
z.string().trim().email()
```

### 3.2 XSS (Cross Site Scripting) Pasivo
Si guardas `<script>alert(1)</script>` en la DB:
*   **En la DB:** No pasa nada (es solo texto).
*   **Al mostrarlo en React:** React escapa por defecto (seguro).
*   **Al mostrarlo en HTML puro:** ¡Peligro!
*   **Solución:** Usa `DOMPurify` (o librerías como `xss`) SOLO cuando vayas a renderizar HTML crudo. **No sanitices en la entrada** (vas a corromper datos legítimos como contraseñas con caracteres especiales).

## 4. Subida de Archivos (Multipart/Form-Data)

JSON no soporta archivos binarios (bueno, en Base64 sí, pero es lento).
Usamos **Multer**.

### 4.1 Configuración Básica
```javascript
const multer = require('multer');
const upload = multer({ dest: 'uploads/' }); // Carpeta temporal

app.post('/avatar', upload.single('foto'), (req, res) => {
    console.log(req.file); 
    // { path: 'uploads/abc-123', originalname: 'foto.jpg', mimetype: 'image/jpeg' }
    res.send("Archivo subido");
});
```
*   **Nota:** Esto guarda el archivo con un nombre aleatorio sin extensión. Necesitas renombrarlo o subirlo a S3.

## 5. Advanced File Uploads (Multer Pro)

Subir archivos sin validar es pedir a gritos un hackeo (Shell Upload).

### 5.1 Filtrado de Archivos (File Filter)
Solo acepta imágenes reales, no `.php` renombrado a `.jpg`.
```javascript
const fileFilter = (req, file, cb) => {
    if (file.mimetype === 'image/jpeg' || file.mimetype === 'image/png') {
        cb(null, true); // Aceptar
    } else {
        cb(new Error('Formato no soportado'), false); // Rechazar
    }
};

const upload = multer({ 
    storage: multer.memoryStorage(), // Guardar en RAM (Buffer)
    limits: { fileSize: 5 * 1024 * 1024 }, // 5MB máx
    fileFilter: fileFilter 
});
```

### 5.2 Storage Engines (Cloud)
No guardes archivos en el disco del servidor (Heroku borra el disco cada 24h).
Usa `multer-s3`.

## 6. CSRF (Cross-Site Request Forgery)

El ataque silencioso.
Si el usuario está logueado en tu banco y visita `hacker.com`, el hacker puede hacer un POST invisible a `tubanco.com/transferir`.

### 6.1 El patrón Double Submit Cookie
1.  Servidor envía una Cookie `XSRF-TOKEN` (No HttpOnly).
2.  Frontend lee esa cookie y la envía en el Header `X-XSRF-TOKEN`.
3.  Servidor verifica que Cookie == Header.
*   **Por qué funciona:** El hacker puede enviar cookies automáticamente, pero **no puede leerlas** (Same-Origin Policy). Si no puede leerla, no puede ponerla en el Header.

```javascript
/* Middleware CSRF (usando csurf o similar) */
app.use(csrf({ cookie: true }));

app.get('/form', (req, res) => {
    // Inyectar token en el HTML o JSON
    res.json({ csrfToken: req.csrfToken() });
});
```

## 7. CAPTCHA (Protección contra Bots)

Si tienes un formulario público (Registro/Login), te van a spammear.

### 7.1 Validación Backend (ReCaptcha v3)
El Frontend te envía un `token`. Tú debes preguntarle a Google si es válido.

```javascript
app.post('/registro', async (req, res) => {
    const { token, email } = req.body;
    
    // Verificar con Google
    const url = `https://www.google.com/recaptcha/api/siteverify?secret=${SECRET}&response=${token}`;
    const googleRes = await fetch(url, { method: 'POST' }).then(r => r.json());
    
    if (!googleRes.success || googleRes.score < 0.5) {
        return res.status(400).json({ error: "Eres un Robot" });
    }
    
    // Si llegas aquí, es humano
    crearUsuario(email);
});
```
*   **Nota:** Nunca confíes solo en el frontend. La validación real ocurre en el backend.

## 8. Formularios Multi-paso (Wizards)

"Paso 1: Datos Personales" -> Siguiente -> "Paso 2: Dirección".
HTTP es stateless. Si refrescas la página, pierdes el Paso 1.

### 8.1 Persistencia Temporal (Redis/Session)
No guardes en DB sql hasta el final. Guarda en un "Draft" en Redis.

```javascript
app.post('/wizard/step1', (req, res) => {
    req.session.draft = { ...req.session.draft, ...req.body };
    res.json({ ok: true });
});

app.post('/wizard/submit', async (req, res) => {
    const finalData = { ...req.session.draft, ...req.body };
    await db.users.create(finalData);
    req.session.draft = null; // Limpiar
});
```

## 9. Validación en Tiempo Real (Debounce)

El usuario escribe "usuar". ¿Verificas si existe en cada tecla? **NO**.
Esperas a que deje de escribir (Debounce).

### 9.1 Backend Check
Ruta ligera para verificar disponibilidad.
```javascript
app.get('/check-username/:username', async (req, res) => {
    const exists = await db.users.count({ username: req.params.username });
    res.json({ available: exists === 0 });
});
```
*   **Tip:** Usa índices en la DB (`CREATE INDEX ON users(username)`).

## 10. Streaming Uploads (Busboy)

Multer carga el archivo en RAM o Disco.
¿Qué pasa si suben un archivo de 10GB? Se acaba la RAM.
Tus datos deben fluir como el agua (Streams).

```javascript
const Busboy = require('busboy');

app.post('/upload-big', (req, res) => {
    const busboy = Busboy({ headers: req.headers });
    
    busboy.on('file', (name, file, info) => {
        // 'file' es un ReadableStream
        // Conéctalo directo a S3 sin tocar el disco del servidor
        file.pipe(s3UploadStream(name));
    });
    
    busboy.on('finish', () => res.send('Subida Exitosa'));
    req.pipe(busboy);
});
```

## 11. Procesamiento de Excel y CSV

Los usuarios aman Excel. Tu app debe amarlo también.

### 11.1 CSV Streams (Rendimiento)
Leer un CSV de 1GB línea por línea sin colapsar la RAM.
```javascript
const csv = require('csv-parser');

fs.createReadStream('usuarios.csv')
  .pipe(csv())
  .on('data', (row) => {
      // Procesar cada fila individualmente
      db.users.create(row);
  })
  .on('end', () => {
      console.log('CSV procesado exitosamente.');
  });
```

### 11.2 Generando Excel (`xlsx`)
```javascript
const XLSX = require('xlsx');

const data = [{ nombre: "Juan", edad: 30 }, { nombre: "Ana", edad: 25 }];
const ws = XLSX.utils.json_to_sheet(data);
const wb = XLSX.utils.book_new();
XLSX.utils.book_append_sheet(wb, ws, "Usuarios");

// Enviar al cliente
const buffer = XLSX.write(wb, { type: 'buffer', bookType: 'xlsx' });
res.setHeader('Content-Type', 'application/vnd.openxmlformats');
res.send(buffer);
```

## 12. Formularios Dinámicos (JSON Driven)

Si tu formulario tiene 500 campos que cambian cada mes, no escribas HTML.
Guarda la estructura en DB.

### 12.1 Schema Definition
```json
{
  "fields": [
    { "type": "text", "name": "nombre", "label": "Nombre Completo", "required": true },
    { "type": "select", "name": "pais", "options": ["MX", "CO", "AR"] }
  ]
}
```

### 12.2 Validación Dinámica
Tu backend debe construir el validador Zod al vuelo basándose en el JSON.
```javascript
function buildValidator(schema) {
    const shape = {};
    schema.fields.forEach(field => {
        if (field.type === 'text') shape[field.name] = z.string();
        if (field.required) shape[field.name] = shape[field.name].min(1);
    });
    return z.object(shape);
}
```

form.getTextField('nombre_cliente').setText('Juan Pérez');

## 14. WebAuthn (Adiós Passwords)

Usar FaceID / TouchID en tu web.
El formulario más seguro es el que no tiene contraseña.

1.  **Registro:** Servidor envía un "Challenge". Navegador pide huella. Servidor guarda la llave pública.
2.  **Login:** Servidor envía "Challenge". Navegador firma con huella (llave privada). Servidor verifica con llave pública.
*   **Librería:** `@simplewebauthn/server`

## 15. Honeypot (Anti-Spam sin molestar)

Los Captchas odian a tus usuarios. Usa un Honeypot.
Es un campo invisible que solo los bots llenan.

```html
<form action="/registro" method="POST">
    <!-- Visible -->
    <input type="email" name="email">
    
    <!-- Invisible para humanos, visible para bots -->
    <div style="display: none;">
        <input type="text" name="website" tabindex="-1" autocomplete="off">
    </div>
    
    <button type="submit">Enviar</button>
</form>
```

```javascript
app.post('/registro', (req, res) => {
    // Si el bot llenó el campo oculto "website"
    if (req.body.website) {
        // Fingir éxito para confundir al bot
        return res.json({ msg: "Registro exitoso" });
    }
    
    crearUsuario(req.body.email);
});
```

## 16. Audit Logging (Auditoría)

En sistemas empresariales, "Quién hizo Qué y Cuándo" es legalmente obligatorio.
No lo mezcles con `console.log`.

```javascript
/* audit.service.js */
async function logAudit(action, actorId, resourceId, metadata) {
    await db.auditLogs.create({
        action: action, // "UPDATE_PROFILE"
        actorId: actorId, // Usuario que hizo el cambio
        resourceId: resourceId,
        ip: metadata.ip,
        changes: JSON.stringify(metadata.diff), // Antes vs Después
        timestamp: new Date()
    });
}

/* controller.js */
app.patch('/users/:id', async (req, res) => {
    const oldUser = await db.users.find(req.params.id);
    await db.users.update(req.params.id, req.body);
    
    logAudit('UPDATE_USER', req.user.id, req.params.id, {
        diff: jsonDiff(oldUser, req.body),
        ip: req.ip
    });
});
```

## 17. GDPR y Consentimiento

Si tienes usuarios en Europa, no puedes pre-marcar el checkbox de "Acepto Newsletter".

### 17.1 Granularidad
*   Checkbox 1: Acepto Términos (Obligatorio).
*   Checkbox 2: Marketing (Opcional, Desmarcado por defecto).
*   Checkbox 3: Compartir con Terceros (Opcional).

### 17.2 Derecho al Olvido
Debes tener una ruta para borrar TODO rastro del usuario (incluyendo Logs y Backups).
```javascript
app.delete('/me/gdpr', async (req, res) => {
    // 1. Borrar DB
    await db.users.delete(req.user.id);
    // 2. Anonimizar Logs (Actualizar email por 'deleted@gdpr')
    await db.auditLogs.updateMany({ actorId: req.user.id }, { actorId: null });
    // 3. Borrar S3
    await s3.deleteFolder(`users/${req.user.id}`);
});
```

## 18. Procesamiento de Imágenes (`Sharp`)

Si el usuario sube una foto de 10MB (4000x3000px), no la guardes así.
Redimensiónala y conviértela a WebP antes de guardar.

```javascript
const sharp = require('sharp');

app.post('/avatar', upload.single('foto'), async (req, res) => {
    // req.file.buffer tiene la imagen cruda
    const optimizedBuffer = await sharp(req.file.buffer)
        .resize(500, 500, { fit: 'cover' }) // Recortar al centro
        .webp({ quality: 80 }) // Comprimir
        .toBuffer();
        
    await s3.upload({ 
        Bucket: 'avatars', 
        Key: `${req.user.id}.webp`, 
        Body: optimizedBuffer 
    });
    
    res.json({ url: `https://cdn.com/${req.user.id}.webp` });
});
```
*   **Performance:** `Sharp` usa librerías de C++ ultra rápidas (libvips). Es 5x más rápido que ImageMagick.

## 19. Streaming Downloads (Descargas)

Si generas un PDF de 50MB, no lo guardes en disco.
Envíalo directo al usuario mientras se genera.

```javascript
app.get('/download/report', async (req, res) => {
    res.setHeader('Content-Type', 'text/csv');
    res.setHeader('Content-Disposition', 'attachment; filename="reporte.csv"');
    
    const cursor = db.users.find().cursor();
    
    // Transform Stream: Objeto JS -> String CSV
    const transform = new Transform({
        objectMode: true,
        transform(user, encoding, callback) {
            this.push(`${user.id},${user.email}\n`);
            callback();
        }
    });

    cursor.pipe(transform).pipe(res);
});
```

## 20. Zero-Trust Security (CSP)

Evita que los formularios carguen scripts maliciosos.
Header: `Content-Security-Policy`.

```javascript
const helmet = require('helmet');

app.use(helmet.contentSecurityPolicy({
    directives: {
        defaultSrc: ["'self'"],
        scriptSrc: ["'self'", "https://www.google.com/recaptcha/"],
        formAction: ["'self'", "https://checkout.stripe.com"]
    }
}));
```
*   **Form Action:** Impide que un `<form>` envíe datos a `hacker.com` incluso si logran inyectarlo.

## 21. Replay Attacks (Ataques de Repetición)

Si un hacker captura tu petición de "Enviar $100" (incluso encriptada en HTTPS) y la reenvía 50 veces... ¿te quedas pobre?
Usa **Nonces** (Number Used Once) y **Timestamps**.

1.  **Header:** `X-Timestamp: 1700000000`.
2.  **Header:** `X-Nonce: abc-123`.
3.  **Firma:** HMAC(Body + Timestamp + Nonce).

**Validación Backend:**
1.  Si `Timestamp` es más viejo de 5min -> Rechazar.
2.  Si `Nonce` ya existe en Redis -> Rechazar.
3.  Si la Firma no coincide -> Rechazar.
