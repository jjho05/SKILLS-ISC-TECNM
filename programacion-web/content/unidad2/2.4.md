# 2.4 Formularios: La Puerta de Entrada de Datos

## 1. Introducción

Los formularios son la única forma en que el usuario puede *hablar* con el servidor.
Son el componente más complejo y crítico de HTML. Un formulario mal hecho te cuesta dinero (ventas perdidas).

---

## 2. La Etiqueta `<form>`

Es el contenedor padre. Sin él, los inputs no saben a dónde enviar los datos.

```html
<form action="/login" method="POST" enctype="multipart/form-data">
    <!-- Inputs aquí -->
</form>
```

### 2.1 Atributos Críticos
*   **`action`:** La URL del backend que recibirá los datos (`/api/users`).
*   **`method`:**
    *   **GET:** Envía los datos en la URL (`/login?user=juan`).
        *   *Uso:* Búsquedas, filtros. NUNCA para contraseñas.
    *   **POST:** Envía los datos en el cuerpo de la petición (ocultos).
        *   *Uso:* Crear, guardar, login.
*   **`enctype`:**
    *   `application/x-www-form-urlencoded` (Por defecto): Texto simple.
    *   `multipart/form-data`: OBLIGATORIO si subes archivos (`<input type="file">`).
*   **`novalidate`:** Desactiva la validación automática del navegador (útil si vas a validar con JS manual).

---

## 3. Tipos de Input Clásicos

Estos existen desde los 90s y funcionan hasta en una tostadora.

### 3.1 Texto y Secretos
*   `<input type="text">`: Una sola línea.
*   `<input type="password">`: Oculta los caracteres (`****`).
    *   *Nota:* No cifra nada. Se envía como texto plano si no usas HTTPS.

### 3.2 Selección
*   **Checkbox:** Selección múltiple "Sí/No".
    *   `<input type="checkbox" checked>` (Marcado por defecto).
*   **Radio:** Selección única (Solo uno del grupo puede estar activo).
    *   *Clave:* Todos deben tener el mismo `name`.
    ```html
    <input type="radio" name="sexo" value="H"> Hombre
    <input type="radio" name="sexo" value="M"> Mujer
    ```

### 3.3 Archivos
*   `<input type="file" accept=".jpg, .png" multiple>`
    *   `multiple`: Permite seleccionar varios archivos con Ctrl.

### 3.4 Ocultos
*   `<input type="hidden" value="123">`: El usuario no lo ve, pero se envía al servidor. Útil para IDs o Tokens de seguridad.

---

## 4. Tipos de Input Modernos (HTML5)

Mejoran la UX en móviles (cambian el teclado).

### 4.1 Datos de Contacto
*   `<input type="email">`: Valida que tenga un `@`. En móvil muestra teclado con `@`.
*   `<input type="tel">`: Muestra teclado numérico.
*   `<input type="url">`: Valida `http://...`.

### 4.2 Números y Rangos
*   `<input type="number" min="0" max="100" step="5">`: Caja con flechitas (spinners). Evita letras.
*   `<input type="range">`: Slider deslizante.

### 4.3 Fechas y Color
*   `<input type="date">`: Calendario nativo.
*   `<input type="time">`: Reloj.
*   `<input type="color">`: Selector de color (Pipeta).

---

## 5. Etiquetas de UX y Accesibilidad

Un input sin label es inaccesible.

### 5.1 `<label>`
Vincula un texto con un input. Al hacer clic en el texto, se activa el input.
```html
<label for="nombre">Tu Nombre:</label>
<input id="nombre" type="text">
```
*   *Alternativa:* Anidar el input dentro del label. `<label>Nombre <input></label>`.

### 5.2 `<fieldset>` y `<legend>`
Agrupa inputs relacionados visual y semánticamente.
```html
<fieldset>
    <legend>Datos de Envío</legend>
    <input type="text" placeholder="Calle">
    <input type="text" placeholder="Ciudad">
</fieldset>
```

### 5.3 `<datalist>` (Autocompletado)
Como un `<select>`, pero permite escribir algo nuevo.
```html
<input list="sabores">
<datalist id="sabores">
    <option value="Vainilla">
    <option value="Chocolate">
    <option value="Fresa">
</datalist>
```

## 6. Atributos de Validación y Comportamiento

HTML5 valida por ti sin una sola línea de JS.

### 6.1 Validación
*   **`required`:** El campo es obligatorio.
*   **`minlength` / `maxlength`:** Longitud del texto.
*   **`min` / `max`:** Valor numérico.
*   **`pattern`:** Expresión Regular (Regex).
    *   `pattern="[0-9]{3}"`: Solo acepta 3 números.

### 6.2 UX
*   **`placeholder`:** Texto fantasma de ayuda (`Ej. Juan Pérez`).
*   **`autofocus`:** Pone el cursor ahí al cargar la página.
*   **`autocomplete`:** Ayuda al navegador a rellenar datos.
    *   `autocomplete="username"`
    *   `autocomplete="current-password"`
    *   `autocomplete="new-password"` (Evita que el navegador sugiera una contraseña vieja).

## 7. API de Validación de Restricciones (Constraint Validation API)

El HTML dice "Este campo es requerido", pero el navegador muestra una burbuja fea y genérica: "Please fill out this field".
Con JavaScript podemos personalizar esto usando la API nativa.

### 7.1 Métodos y Propiedades
Todo input tiene estas propiedades en JS:
*   `validity`: Un objeto con el estado del error (`validity.valueMissing`, `validity.typeMismatch`, `validity.tooShort`).
*   `validationMessage`: El mensaje de error actual.
*   `checkValidity()`: Devuelve `true` si es válido.
*   `setCustomValidity("Mensaje")`: Define un error personalizado.

### 7.2 Ejemplo: Personalizando el Mensaje
```javascript
const emailInput = document.getElementById('email');

emailInput.addEventListener('input', (event) => {
  if (emailInput.validity.typeMismatch) {
    emailInput.setCustomValidity('¡Oye! Eso no parece un correo real (falta el @).');
  } else {
    emailInput.setCustomValidity(''); // String vacío significa "Válido"
  }
});
```

## 8. Estilizando Formularios con CSS (Pseudo-clases)

Olvídate de agregar y quitar clases como `.error` manualmente. CSS tiene estados nativos.

### 8.1 Estados de Validación
*   `:valid`: El input cumple las reglas. (Píntalo verde).
*   `:invalid`: El input tiene errores. (Píntalo rojo).
    *   *Nota:* Se activa desde que carga la página. Para evitar mostrar errores en campos vacíos, usa `:placeholder-shown` o JS.
*   `:required`: Campos obligatorios (puedes ponerles un asterisco `*` con `::after`).
*   `:optional`: Campos opcionales.

### 8.2 Estados de Interacción
*   `:focus`: Cuando el usuario está escribiendo.
*   `:focus-visible`: Solo cuando navega con teclado (anillo azul).
*   `:disabled`: Inputs desactivados.
*   `:read-only`: Inputs que no se pueden editar pero sí leer y copiar.

### 8.3 El Truco del Label Flotante (Material Design)
Usando `:placeholder-shown` y `+` (selector adyacente sibling).

```css
input:not(:placeholder-shown) + label,
input:focus + label {
    transform: translateY(-20px);
    font-size: 12px;
    color: blue;
}
```

## 9. Seguridad en Formularios: Protegiendo al Usuario

Los formularios son el vector de ataque #1.

### 9.1 CSRF (Cross-Site Request Forgery)
Un atacante te manda un link: `malvado.com/premio`. Al entrar, esa página envía un formulario oculto a `tubanco.com/transferir`. Como ya estabas logueado en tu banco, la transferencia se hace.

**Solución: CSRF Token**
Un input oculto con un código secreto que solo tu servidor conoce.
```html
<input type="hidden" name="csrf_token" value="e892na8s98d...">
```
Si el formulario no trae este token, el servidor rechaza la petición.

### 9.2 XSS (Cross-Site Scripting)
Si permites que el usuario escriba `<script>alert(1)</script>` en un comentario y luego lo muestras tal cual en la web, acabas de hackear a todos tus visitantes.

**Solución:**
1.  **Sanitización:** Limpia el HTML en el backend (quita los `<script>`).
2.  **Escape:** Convierte `<` en `&lt;`.

### 9.3 Captcha y Honeypot (Anti-Spam)
*   **ReCaptcha/hCaptcha:** Poner a los usuarios a identificar semáforos. (Molesto pero efectivo).
*   **Honeypot (Olla de Miel):** Un campo oculto (`display: none`) llamado "website" o "phone".
    *   Los humanos no lo ven y lo dejan vacío.
    *   Los bots llenan TODO.
    *   *Lógica Backend:* Si el campo "website" tiene texto, es un bot -> Bloquear.

## 10. Subida de Archivos Avanzada (`<input type="file">`)

El input de archivo por defecto es horrible ("Seleccionar archivo" gris).
No se puede estilar directamente.

### 10.1 El Hack del Label
Oculta el input real y estila el label conectado a él.

```html
<input type="file" id="mi-archivo" class="input-file" hidden>
<label for="mi-archivo" class="btn-subir">
    📂 Subir CV
</label>
```
Al hacer clic en el label, el navegador dispara el click en el input oculto.

### 10.2 Drag and Drop API
Para arrastrar archivos a la zona.
Requiere JS avanzado (`dragover`, `drop`, `DataTransfer`), pero mejora la UX infinitamente.

### 10.3 Previsualización de Imagen
Muestra la foto antes de subirla al servidor.
```javascript
input.onchange = evt => {
    const [file] = input.files;
    if (file) {
        previewImg.src = URL.createObjectURL(file);
    }
}
```

## 11. Accesibilidad en Formularios (WAI-ARIA)

Crear formularios accesibles es ley (literalmente en muchos países).

### 11.1 Errores Accesibles
No basta con poner el borde rojo. Un ciego no ve el borde rojo.
Tienes que *vincular* el mensaje de error con el input.

```html
<label for="email">Email:</label>
<input type="email" id="email" aria-describedby="email-error" aria-invalid="true">

<span id="email-error" class="error">El correo es inválido.</span>
```
Cuando el input tenga foco, el lector dirá: *"Email, entrada de texto inválida. El correo es inválido."*

### 11.2 Grupos de Checkboxes
Usa `<fieldset>` y `<legend>` siempre.
```html
<fieldset>
    <legend>Elige tus ingredientes:</legend>
    <label><input type="checkbox"> Queso</label>
    <label><input type="checkbox"> Jamón</label>
</fieldset>
```
Sin esto, el lector solo dice "Checkbox, Queso". Con esto dice "Elige tus ingredientes: Checkbox, Queso".

## 13. Glosario de Formularios

*   **Autofill:** Cuando el navegador rellena el formulario por ti (ej. tu dirección).
*   **Blob:** Binary Large Object. Representación de un archivo en memoria JS.
*   **Controles de Formulario:** Inputs, selects, textareas, botones.
*   **Multipart/form-data:** El tipo de codificación necesario para subir archivos binarios (fotos, pdfs).
*   **Placeholder:** Texto de ayuda temporal. NO reemplaza al label.
*   **Query String:** La parte de la URL después del `?` (`?q=gatos`).
*   **Submit:** La acción de enviar el formulario al servidor.
*   **Validation Bubble:** El mensaje nativo del navegador ("Rellene este campo").

## 15. Expresiones Regulares (Regex): Validación Nivel Dios

El atributo `pattern` usa Regex. Es un lenguaje críptico pero poderoso.

### 15.1 Chuleta Básica
*   `^`: Inicio de línea.
*   `$`: Fin de línea.
*   `[a-z]`: Cualquier letra minúscula.
*   `[0-9]` o `\d`: Cualquier número.
*   `{3}`: Exactamente 3 veces.
*   `{3,}`: 3 o más veces.
*   `+`: Una o más veces.
*   `*`: Cero o más veces (Cuidado, acepta cadenas vacías).

### 15.2 Recetario Mexicano (RFC y CURP)

**RFC (Persona Física):** 4 letras, 6 números, 3 homoclave.
`pattern="^[A-Z&Ñ]{4}\d{6}[A-Z0-9]{3}$"`
*   Explicación:
    *   `^[A-Z&Ñ]{4}`: Empieza con 4 letras mayúsculas (incluye Ñ y &).
    *   `\d{6}`: Sigue con 6 dígitos (Fecha YYMMDD).
    *   `[A-Z0-9]{3}$`: Termina con 3 caracteres alfanuméricos.

**CURP:** 4 letras, 6 números, 1 letra (H/M), 5 letras (Estado/Consonantes), 2 dígitos.
`pattern="^[A-Z]{4}\d{6}[HM][A-Z]{5}[A-Z0-9]{2}$"`

### 15.3 Contraseña Segura
Mínimo 8 caracteres, 1 mayúscula, 1 minúscula, 1 número.
`pattern="(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}"`
*   Usa "Lookaheads" `(?=...)` para verificar condiciones múltiples en cualquier orden.

## 16. Patrones de Diseño de Formularios (UX)

No basta con que funcione. Tiene que ser fácil de usar.

### 16.1 Wizard (Pasos Múltiples)
Si tienes 50 campos, no los muestres todos de golpe. Divide y vencerás.
1.  **Paso 1:** Datos de Cuenta.
2.  **Paso 2:** Dirección.
3.  **Paso 3:** Pago.
*   *Implementación:* Usa 3 `<fieldset>` y oculta 2 con CSS/JS. Muestra una barra de progreso.

### 16.2 Inline Validation (Validación en Línea)
*   **Mal:** El usuario llena 20 campos, le da "Enviar", y la página recarga con 5 errores arriba.
*   **Bien (On Blur):** Cuando el usuario *sale* de un campo (`blur`), valídalo y muestra el error ahí mismo.
*   **Mejor (On Input - con debounce):** Validar mientras escribe (ej. fortaleza de contraseña), pero esperar a que termine de escribir para errores de formato (email).

### 16.3 Floating Labels (Material Design)
El label está dentro del input (como placeholder). Al hacer click, flota hacia arriba y se hace pequeño.
*   *Ventaja:* Ahorra espacio vertical en móviles.
*   *Desventaja:* Si no está bien hecho, se confunde con el valor ya escrito.

## 17. La API `FormData` y el Envío sin Recarga (AJAX)

En la web moderna (SPAs), no queremos que la página parpadee al enviar. Usamos JS.

### 17.1 Interceptando el Envío
```javascript
const form = document.querySelector('form');

form.addEventListener('submit', (e) => {
    e.preventDefault(); // 1. Detiene la recarga
    
    // 2. Captura los datos mágicamente
    const data = new FormData(form);
    
    // 3. Imprime los valores
    console.log(data.get('username'));
    console.log(Object.fromEntries(data)); // Convierte a JSON simple
});
```

### 17.2 Enviando al Servidor (Fetch API)
```javascript
fetch('/api/register', {
    method: 'POST',
    body: new FormData(form) // El navegador pone el Content-Type correcto automáticamente
})
.then(response => response.json())
.then(data => alert('¡Guardado!'));
```

## 18. Estilizando lo "In-estilizable"

Checkboxes y Radios nativos son feos y diferentes en cada navegador.
La técnica moderna para personalizar ckeckboxes:

```css
/* 1. Ocultar el input nativo (pero mantenerlo accesible) */
input[type="checkbox"] {
    appearance: none; /* Resetea el estilo nativo */
    -webkit-appearance: none;
    width: 20px;
    height: 20px;
    border: 2px solid gray;
    border-radius: 4px;
    cursor: pointer;
    display: grid;
    place-content: center;
}

/* 2. El estado checked */
input[type="checkbox"]:checked {
    background-color: blue;
    border-color: blue;
}

/* 3. La palomita (usando pseudo-elemento) */
input[type="checkbox"]::before {
    content: "✔";
    color: white;
    font-size: 14px;
    transform: scale(0); /* Oculto por defecto */
    transition: 120ms transform;
}

input[type="checkbox"]:checked::before {
    transform: scale(1); /* Visible */
}
```

## 19. Accesibilidad Profunda en Formularios

### 19.1 `aria-live` y `role="alert"`
Cuando aparece un error dinámicamente con JS, el lector de pantalla NO lo lee automáticamente a menos que le avises.

```html
<div role="alert" aria-live="polite">
    <!-- Si JS inyecta texto aquí, el lector lo dirá inmediatamente -->
</div>
```
*   `polite`: Espera a que el usuario termine de hablar/escribir.
*   `assertive`: Interrumpe al usuario (Úsalo solo para errores críticos).

### 19.2 Cambios de Contexto
Nunca hagas que un formulario se envíe automáticamente al seleccionar una opción en un `<select>` (`onchange="submit()"`).
Esto desorienta terriblemente a los usuarios de teclado. Siempre requiere un botón explícito "Enviar" o "Aplicar filtros".

## 20. Auditoría de Seguridad: Errores Comunes

### 20.1 Confiar en la Validación Frontend
**Mito:** "Si pongo `min="18"` en el input de edad, nadie menor de 18 entrará".
**Realidad:** Yo puedo abrir la consola, borrar `min="18"`, o enviar una petición `curl` directa al servidor con `age=5`.
**Regla:** La validación HTML/JS es cosmética. La validación REAL está en el Servidor (PHP, Node, Java).

### 20.2 Exponer IDs en Inputs Ocultos
`<input type="hidden" name="user_id" value="admin">`
Si veo esto, lo cambiaré a `value="superadmin"`. Nunca confíes en datos que "vienen de vuelta" del cliente.

## 22. Proyecto Final: E-commerce Checkout (Nivel Experto)

Vamos a armar un formulario de pago que cumpla con TODOS los estándares de 2025.

### 22.1 Estructura HTML
```html
<form class="checkout-form" action="/pay" method="POST">
    
    <!-- Progreso Semántico -->
    <nav aria-label="Progreso de compra">
        <ol class="steps">
            <li class="completed">Carrito</li>
            <li aria-current="step">Pago</li>
            <li>Confirmación</li>
        </ol>
    </nav>

    <!-- Sección 1: Tarjeta de Crédito -->
    <fieldset class="payment-group">
        <legend>Datos de Pago</legend>
        
        <div class="row">
            <div class="col-full">
                <label for="cc-name">Nombre en la tarjeta</label>
                <input type="text" id="cc-name" name="cc-name" 
                       required autocomplete="cc-name"
                       pattern="[A-Za-z ]{4,}"
                       placeholder="JESUS OLVERA">
            </div>
            
            <div class="col-full">
                <label for="cc-number">Número de tarjeta</label>
                <input type="text" id="cc-number" name="cc-number" 
                       required autocomplete="cc-number"
                       inputmode="numeric" 
                       pattern="[0-9\s]{13,19}"
                       placeholder="0000 0000 0000 0000">
                <!-- Icono de tarjeta detectado vía JS -->
                <span id="cc-brand" aria-hidden="true"></span>
            </div>
            
            <div class="col-half">
                <label for="cc-exp">Expiración (MM/YY)</label>
                <input type="text" id="cc-exp" name="cc-exp" 
                       required autocomplete="cc-exp"
                       placeholder="MM/YY"
                       pattern="(0[1-9]|1[0-2])\/?([0-9]{2})">
            </div>
            
            <div class="col-half">
                <label for="cc-cvc">CVC</label>
                <input type="text" id="cc-cvc" name="cc-cvc" 
                       required autocomplete="cc-csc"
                       inputmode="numeric" 
                       pattern="[0-9]{3,4}"
                       maxlength="4">
                <button type="button" aria-label="¿Qué es el CVC?" onclick="showHelp()">?</button>
            </div>
        </div>
    </fieldset>

    <!-- Sección 2: Dirección (Reutilizando datos) -->
    <fieldset>
        <legend>Dirección de Facturación</legend>
        <label class="checkbox-wrapper">
            <input type="checkbox" name="same-address" checked onchange="toggleAddress()">
            Usar la misma dirección de envío
        </label>
        
        <div id="billing-fields" hidden>
            <!-- Campos extra aquí -->
            <label for="street">Calle:</label>
            <input type="text" id="street" name="street" autocomplete="street-address">
        </div>
    </fieldset>

    <div class="actions">
        <!-- Prevent Double Submit -->
        <button type="submit" id="btn-pay">Pagar $1,200.00 MXN</button>
    </div>
</form>
```

### 22.2 Notas de Ingeniería
1.  **`autocomplete` es ORO:** Usamos `cc-name`, `cc-number`, `cc-exp`. Esto permite que Chrome/Safari rellenen la tarjeta con un clic (incluido FaceID).
2.  **`inputmode="numeric"`:** En iPhone, abre el teclado de números grandes (teléfono), pero permite caracteres especiales (espacios). Es mejor que `type="number"` para tarjetas.
3.  **Accesibilidad:** Usamos `<nav aria-label>` para los pasos y `aria-hidden` para adornos visuales.

## 23. Depuración: Herramientas del Navegador

¿Cómo sabes qué diablos se envió al servidor?

1.  Abre DevTools (F12) -> Pestaña **Network**.
2.  Activa la casilla **"Preserve Log"** (Importante, si no, al recargar se borra todo).
3.  Envía el formulario.
4.  Busca la petición (usualmente el nombre del archivo del `action` o la última en la lista).
5.  Ve a la pestaña **Payload** (o Params).
    *   Ahí verás el JSON o el Form Data decodificado. Si ves `[object Object]`, tu JS está mal.

## 24. El Futuro de los Formularios: `inert` y `popover`

HTML sigue evolucionando.

### 24.1 Atributo `inert`
Cuando abres un modal de "Confirmar Pago", el resto del formulario debe quedar congelado (no clicable, no tabulable).
Antes: `pointer-events: none` + JS complejo.
Ahora:
```html
<form inert>
   <!-- Todo esto está congelado y fuera del árbol de accesibilidad -->
</form>
```

### 24.2 API Popover (2024)
Para los tooltips de ayuda ("¿Qué es el CVC?").
```html
<button popovertarget="help-cvc">¿Ayuda?</button>

<div id="help-cvc" popover>
  El CVC son los 3 números al reverso...
</div>
```
*   Sin una sola línea de JS. Nativo.
