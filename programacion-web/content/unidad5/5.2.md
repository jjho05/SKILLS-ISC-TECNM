# 5.2. Tipos de Servicios en la Nube (El Menú del Restaurante)

Entras a la consola de AWS y ves 200 servicios. ¿Cuál usas?
Aquí desglosamos los grupos principales.

---

## 1. Cómputo (El Cerebro)

Donde se ejecuta tu código.

### 1.1 Máquinas Virtuales (EC2 / Azure VM)
*   **¿Qué es?** Un servidor Linux/Windows "rentado".
*   **Uso:** Aplicaciones Legacy, Monolitos, Bases de Datos Self-Hosted.
*   **Gestión:** Alta. Tienes que parchear el SO, configurar Firewall, instalar Node.
*   **Conceptos Clave:**
    *   **Familias:** `t3` (General), `c6` (Compute Op), `r6` (Memory Op).
    *   **AMI (Amazon Machine Image):** La "foto" del disco para arrancar (Ubuntu 22).

### 1.2 Contenedores (ECS / EKS / Cloud Run)
*   **¿Qué es?** Orquestación de Docker.
*   **Uso:** Microservicios, Apps Modernas.
*   **Gestión:** Media. AWS gestiona el "Cluster", tú gestionas los "Pods".
*   **AWS Fargate:** Serverless Containers. No administras servidores, solo dices "Quiero 2 CPU y 4GB RAM".

### 1.3 Serverless Functions (Lambda / Azure Functions)
*   **¿Qué es?** Código disparado por eventos.
*   **Uso:** APIs, Procesamiento de imágenes, Cron jobs.
*   **Gestión:** Nula. Solo subes código.
*   **Limitaciones:** Cold Starts (tarda en despertar), Tiempo límite (15 min en Lambda).

---

## 2. Almacenamiento (El Disco Duro)

Donde guardas los datos. No, no se guardan en el servidor (`npm install` borra todo si se reinicia).

### 2.1 Block Storage (AWS EBS)
*   **Analogía:** El disco duro C:/ de tu laptop.
*   **Características:** Rápido, Baja latencia.
*   **Limitación:** Solo se puede conectar a UN servidor a la vez (generalmente). Si el server muere, el disco persiste.

### 2.2 Object Storage (AWS S3)
*   **Analogía:** Google Drive ilimitado programable.
*   **Características:** HTTP API (GET/PUT). Escalabilidad infinita. Barato.
*   **Uso:** Fotos de perfil, Backups, Static Websites (React Apps), Data Lakes.
*   **No sirve para:** Instalar un Sistema Operativo o correr una Base de Datos.

### 2.3 File Storage (AWS EFS)
*   **Analogía:** Una carpeta compartida en red (NAS/NFS).
*   **Características:** Múltiples servidores pueden leer/escribir a la vez.
*   **Uso:** CMS (WordPress) compartiendo media files entre varios servers.

## 3. Bases de Datos (Persistencia Gestionada)

"Managed Service" significa: AWS hace los backups, el patching y el scaling. Tú solo usas la URL.

### 3.1 Relacionales (RDS / Aurora)
*   **Motores:** Postgres, MySQL, SQL Server, Oracle.
*   **Aurora:** Un MySQL reescrito para la nube. 5x rendimiento. Storage auto-escalable.
*   **Feature clave:** "Point-in-time recovery" (Volver al segundo exacto de ayer).

### 3.2 NoSQL (DynamoDB / CosmosDB)
*   **Características:** Key-Value. Milisegundos de un solo dígito a cualquier escala.
*   **Escalado:** Automático. Puedes manejar 1 o 1 millón de req/seg.
*   **Uso:** Carritos de compra, Juegos, Leaderboards.

### 3.3 In-Memory (ElastiCache / Redis)
*   **Uso:** Caché de sesiones, Pub/Sub.
*   **Dato:** Sub-milisegundo (Microsegundos).

## 4. Redes (La Tubería)

Si no configuras esto, nadie entra a tu app.

### 4.1 VPC (Virtual Private Cloud)
Tu pedazo privado de la nube.
*   **Subnets Públicas:** Tienen acceso a Internet (Load Balancer).
*   **Subnets Privadas:** NO tienen acceso directo (Base de Datos). Para salir necesitan un NAT Gateway.
*   **Security Groups:** El firewall virtual (`Allow port 80 from 0.0.0.0/0`).

### 4.2 Load Balancers (ALB)
Distribuye el tráfico entrante entre tus 10 servidores EC2.
*   Terminación SSL (El certificado HTTPS vive aquí, no en tu Node.js).
*   Health Checks (Si el servidor 3 muere, deja de enviarle tráfico).

### 4.3 CDN (CloudFront)
Caché global. Si tu usuario está en China, baja la imagen de un servidor en Beijing, no de Virginia.

### 4.4 API Gateway
La puerta de entrada a tus Microservicios/Lambdas.
*   Rate Limiting (Evita DDoS).
*   Auth (Verifica JWT).
*   Transformación de Requests.

## 5. Analítica y Big Data (El Nuevo Petróleo)

### 5.1 Data Warehouse (Redshift / BigQuery)
*   **¿Qué es?** Una base de datos SQL capaz de procesar Petabytes.
*   **Diferencia con RDS:** RDS es para transacciones (filas). Redshift es para análisis (columnas).
*   **Uso:** Reportes de ventas anuales, Business Intelligence.

### 5.2 Data Lake (S3 + Athena)
*   Tiras todos tus CSV/JSON crudos a S3 (barato).
*   Usas **Athena** para hacer consultas SQL *directamente* sobre los archivos S3 (Serverless SQL).

### 5.3 Streaming (Kinesis / Kafka)
*   Ingesta de datos en tiempo real (Clickstream, Logs de IoT, Geolocalización de Uber).

Define toda tu infraestructura en un archivo YAML/JSON.

## 9. Seguridad e Identidad (Security)

### 9.1 IAM (Identity and Access Management)
*   **Usuarios:** Personas o Servidores.
*   **Roles:** Sombreros que te pones temporalmente.
*   **Políticas:** JSON que dice qué puedes hacer (`Effect: Allow, Action: s3:GetObject`).

### 9.2 Cognito
*   "Login with Facebook/Google" as a Service.
*   Maneja el registro de usuarios, reseteo de password, JWTs.

### 9.3 WAF (Web Application Firewall)
*   Protege contra SQL Injection, XSS y Bots maliciosos antes de que lleguen a tu server.

### 9.4 Shield
*   Protección contra ataques DDoS (Distributed Denial of Service).

## 12. Modelos de Precios (Cómo no quebrar)

AWS te cobra por segundo. Hay 4 formas de pagar por EC2:

### 12.1 On-Demand (A la Carta)
*   **Precio:** El más caro (Precio de lista).
*   **Compromiso:** Ninguno. Prendes, usas, apagas, dejas de pagar.
*   **Uso:** Pruebas, Spikes de tráfico impredecibles, Startups día 1.

### 12.2 Reserved Instances (Reservas)
*   **Precio:** Hasta 72% de descuento.
*   **Compromiso:** Contrato de 1 o 3 años. "Te prometo que usaré este servidor todo el año".
*   **Uso:** Bases de Datos, Servidores centrales que siempre están prendidos.

### 12.3 Spot Instances (La Rebaja)
*   **Precio:** Hasta 90% de descuento.
*   **Condición:** Es la capacidad sobrante de AWS. Si alguien paga el precio full, **te quitan el servidor con 2 minutos de aviso**.
*   **Uso:** Big Data, Renderizado de video, CI/CD, cualquier cosa que pueda interrumpirse.

### 12.4 Savings Plans
*   **Precio:** ~70% descuento.
*   **Compromiso:** "Gastaré $10/hora en Cómputo". No importa qué instancia uses (Flexible).
*   **Uso:** La forma moderna de ahorrar.

## 16. Clases de Almacenamiento S3 (Ahorrando Dinero)

No todos los datos valen lo mismo.
*   **S3 Standard:** Acceso milisegundos. Caro. (Para tu web estática y fotos de perfil).
*   **S3 Intelligent-Tiering:** Una IA mueve tus archivos entre barato y caro según uso.
*   **S3 Standard-IA (Infrequent Access):** Barato de guardar, caro de recuperar. (Para backups mensuales).
*   **S3 Glacier Instant Retrieval:** Archivo profundo. Recuperación en milisegundos.
*   **S3 Glacier Deep Archive:** El más barato del mundo ($1 USD / TB). Recuperación tarda **12 horas**. (Para auditorías legales de hace 5 años).

## 17. Networking Internals (La Fontanería)

¿Por qué mi Lambda no ve Internet?

### 17.1 Route Tables
Es el mapa de tu VPC.
*   "Si el destino es `10.0.0.0/16`, manda el paquete localmente".
*   "Si el destino es `0.0.0.0/0` (Internet), mándalo al Internet Gateway".

### 17.2 Internet Gateway (IGW) vs NAT Gateway
*   **IGW:** Puerta bidireccional. Permite que alguien desde Internet entre a tu servidor Público (Web Server).
*   **NAT Gateway:** Puerta de una sola vía. Tu servidor Privado (DB) puede salir a Internet (descargar updates), pero nadie puede entrar. **Cuesta dinero por hora**.

### 17.3 VPN Site-to-Site
Un cable virtual encriptado entre tu oficina física y tu VPC en AWS.
Tus empleados acceden a los servidores privados con IPs internas (`192.168...`).

## 21. Serverless Avanzado (Más allá de Lambda)

Lambda es solo el cómputo. ¿Cómo orquestas 20 Lambdas?

### 21.1 Step Functions (Máquina de Estados)
Si Lambda A falla, espera 5s y reintenta. Si falla de nuevo, ejecuta Lambda B (Rollback).
*   Esto es difícil de hacer en código (`if/else` gigante).
*   **Step Functions** es un diagrama visual JSON que maneja el flujo y el estado.

### 21.2 EventBridge (El Bus de Eventos)
El sistema nervioso central de tu arquitectura.
*   "Cuando un cliente paga en Shopify (Webhook) -> Enciende una Lambda en AWS".
*   "Cuando se sube un archivo a S3 -> Enciende una Lambda de procesado".
*   Filtra y enruta eventos sin código.

### 21.3 Lambda Layers
¿Tienes `node_modules` de 50MB (lodash, sharp)?
No los subas en cada Deploy.
Crea un **Layer** (ZIP compartido) y úsalo en 20 funciones. Reduce el tiempo de despliegue.

## 22. Ecosistema de Contenedores

Docker es el estándar. AWS tiene herramientas específicas.

### 22.1 ECR (Elastic Container Registry)
Es tuDocker Hub privado.
*   Escanea vulnerabilidades automáticamente (CVEs).
*   Replicación global (Sube la imagen en USA, replícala a Asia en segundos).

### 22.2 Fargate vs EC2 (Launch Type)
En ECS/EKS tienes que decidir *dónde* corren los contenedores.
*   **EC2:** Tú prendes las VMs. Tienes que actualizarlas. Eres dueño del SO. (Más barato si optimizas bien).
*   **Fargate:** Serverless. Solo dices "Dame 1 vCPU". AWS pone la VM oculta. (Más caro por minuto, pero cero administración).

## 26. La Vida de una Petición (Narrativa)

¿Qué pasa cuando escribes `www.miapp.com`?

1.  **Route 53 (DNS):** Traduce el dominio a la IP de CloudFront.
2.  **CloudFront (CDN):** Revisa si tiene el HTML en caché. Si no...
3.  **WAF (Firewall):** Revisa si tu IP es de un hacker ruso. Si no...
4.  **ALB (Load Balancer):** Recibe la petición SSL y la manda al Servidor #3 (el menos ocupado).
5.  **EC2 (Compute):** Tu código Node.js recibe la petición.
6.  **ElastiCache (Redis):** Tu código busca la sesión del usuario.
7.  **RDS (Database):** Tu código lee el perfil del usuario.
8.  **S3 (Storage):** Tu código genera un PDF y lo guarda.
9.  **SES (Email):** Tu código envía un email de confirmación.
10. **Response:** El HTML viaja de regreso pasando por el ALB, WAF y se guarda en CloudFront para el siguiente usuario.

Todo esto ocurre en **200 milisegundos**.

## 27. Arquitecturas Multi-Región (Escala Planetaria)

Si quieres sobrevivir a un terremoto que destruya todo USA East.

### 27.1 Active-Passive (DR)
*   **Región A (Primaria):** Recibe el 100% del tráfico.
*   **Región B (Secundaria):** Tiene una copia de la DB (Read Replica) y servidores apagados.
*   **Failover:** Si A muere, prendes B y actualizas el DNS. (Downtime: 15 mins).

### 27.2 Active-Active (Global)
*   **Región A y B:** Ambas reciben tráfico.
*   **DynamoDB Global Tables:** Si escribes en Tokyo, el dato aparece en New York en 1 segundo.
*   **Failover:** Automático. Si A muere, Route 53 envía todo a B instantáneamente. (Downtime: 0).
*   **Costo:** $$$$$.

## 28. Decisión: ¿Serverless o Contenedores?

| Criterio | Serverless (Lambda) | Contenedores (Fargate/K8s) |
| :--- | :--- | :--- |
| **Tráfico** | Esporádico o Ráfagas (Spikes) | Constante y predecible |
| **Ejecución** | Corta (< 15 min) | Larga (Daemon, WebSocket server) |
| **Control** | Bajo (Solo código) | Alto (SO, Networking, Binarios) |
| **Lenguaje** | Limitado (Node, Python, Java...) | Cualquiera (Si corre en Linux, corre) |
| **Costo** | Pagas por invocación (Barato si poco uso) | Pagas por hora (Barato si uso intensivo) |
| **Cold Start** | Sí (~200ms - 1s) | No (Siempre prendido) |

## 29. Networking Avanzado (Conectando VPCs)

Tienes 50 cuentas de AWS y 100 VPCs. ¿Cómo se hablan?

### 29.1 VPC Peering
*   Conexión 1 a 1.
*   VPC A <-> VPC B.
*   Si tienes 100 VPCs, necesitas un desastre de cables (Malla completa).

### 29.2 Transit Gateway (El Hub)
*   Un Router central gigante en la nube.
*   Todas las VPCs se conectan al Transit Gateway.
*   También conecta tu VPN de oficina.
*   Simplifica la topología de red masiva.

## 30. Infraestructura como Código (Ejemplo Real)

No crees recursos con el mouse. Hazlo con código.

### 30.1 Terraform (HCL)
El estándar de industria multi-nube.

```hcl
provider "aws" {
  region = "us-east-1"
}

# Crear un bucket S3
resource "aws_s3_bucket" "mi_bucket" {
  bucket = "mi-app-fotos-2024"
}

# Crear una Lambda disparada por S3
resource "aws_lambda_function" "procesador" {
  function_name = "ProcesarImagen"
  handler       = "index.handler"
  runtime       = "nodejs18.x"
  s3_bucket     = aws_s3_bucket.mi_bucket.bucket
}
```

### 30.2 AWS CDK (Cloud Development Kit)
Usa TypeScript para crear infraestructura. (Más moderno, imperativo).

```typescript
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as lambda from 'aws-cdk-lib/aws-lambda';

// Crear bucket
const bucket = new s3.Bucket(this, 'MiBucket');

// Crear función
const fn = new lambda.Function(this, 'Procesador', {
  runtime: lambda.Runtime.NODEJS_18_X,
  handler: 'index.handler',
  code: lambda.Code.fromAsset('lambda'),
});

// Dar permisos (Magia de CDK)
bucket.grantRead(fn);
```
